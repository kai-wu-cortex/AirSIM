# VoWLAN 首次接通音频启动

## 修复范围

旧版本在处理 Agent 通话状态后，先等待推送登记、云端状态和实时活动更新，最后才停止 iPhone 等待音和启动本地 PCM。首次登记或外网缓慢时，这些非音频请求可能推迟接通处理。

新版在权威接通事件到达时同步停止等待音，随后优先同步通话状态并启动本地音频。推送与实时活动使用单个合并任务；通话变化、挂断、停止或重启轮询使旧任务失效。原有登记指纹、退避和云端查询次数策略不变。此修复不把拨号成功误当成对方接听，也不跳过 CallKit 音频激活。

### 2026-10-30：APNs 接听期间切前台（未发布）

build 149 的客户端日志记录了 `agent_ready` 紧接 `stopped`，CallKit 的 `DEACTIVATED` 则在约 18 秒后的挂断才出现。服务端同一通话的 PCM 已鉴权、收发数据，随后收到客户端 `peer-end`。启动窗口内也记录了 `foreground call_active=true`。旧版兼容路径把音频有效性绑定到 `pollingGeneration`，且可从轮询任务直接执行启动；前后台刷新使仍有效的通话在登记返回后回滚。日志没有记录旧版具体失效条件，因此不能仅凭该次日志区分世代变化和任务取消。

修复将音频启动交给独立、单飞的任务，CallKit 与轮询等待同一任务；重启轮询仍取消旧查询和补充工作，但不取消音频。兼容路径按通话 ID、UUID、通话 generation、拨号尝试、媒体归属和锁定传输／PCM 路由判断有效性，不再使用轮询 generation。真正挂断／替换通话、AppModel 停止、CallKit 音频停用或 provider 重置会取消在途启动；迟到回滚仅释放自己的 `sessionOwner`，不清理新通话的音频。

此修复不改 APNs 凭据、PCM 协议或服务端超时，不需要据此部署 Relay 或重启服务端。兼容路径回归在旧实现上复现登记成功后回滚，修复后通过；定向 46 项及完整 367 项 XCTest 均通过。独立 Swift 运行检查确认取消轮询不撤销登记、明确取消音频仍回滚。尚未安装或上传 TestFlight。

### 2026-10-31：PR #18 合并评审补充（未发布）

原 PR 的 `cancel()` 仅标记旧启动任务取消；取消后的新请求仍等待旧任务，随后直接返回，导致新启动被吞掉。补充修复采用串行交接：等待旧任务完成自身清理，再检查当前任务槽位，复用其他观察者已经发起的替代任务，或执行当前请求。不会提前清空旧任务、并行启动两套音频，也不会让旧任务的清理覆盖新任务。实际启动仍重新检查当前通话、媒体归属与路由；等待者自身被取消时不能重新拉起音频。

新增测试覆盖取消后的单次交接与多个观察者合并、已取消等待者不重启音频、连续取消后的再次启动。此前 46／367 项结果属于原 PR 验证；整合后的验证记录见 `handoff/2026-10-31-callkit-background-repair.md`。

此改动处理接听后的 PCM 生命周期，不代表“锁屏来电响铃延迟”已修复。延迟仍需分别关联 Agent 发现来电、Worker 收到请求、APNs 接受和 iPhone 收到 PushKit／上报 CallKit 的时间。


## 启动诊断

现有 Agent Verbose TXT 导出会包含 `call-audio` 启动阶段及耗时。即使完整 Verbose 关闭，也保留有限条数的阶段记录；只接受固定阶段，不记录号码、通话标识、密钥、PCM 内容或服务器地址。

- `answer_observed`：收到权威接通状态。
- `phone_start` / `engine_ready`：启动手机音频／引擎就绪，耗时含麦克风授权。
- `agent_register` / `agent_ready`：登记 Agent 音频／登记返回，登记耗时单独计算。
- `pcm_ready` / `first_downlink`：PCM 握手成功／首次提交下行播放，相对手机音频启动计时。收到字节不等于声学质量验证。
- `failed` / `stopped`：失败或停止。
- `rollback`：启动回滚；`reason` 仅取固定值 `task_cancelled`、`call_changed`、`call_not_active`、`media_owner_changed`、`route_changed`、`agent_call_inactive`、`registration_unavailable`、`registration_failed`。不记录通话身份或端点。

## 真机验收

保留原配对和数据覆盖安装后，使用 VoWLAN 发起首次通话。对方接听后，检查等待音停止、双向声音可用；挂断观察是否重现通话页。再测试外网不可达但局域网可用，以及授权弹窗期间挂断。测试不应自动呼叫真实号码。

APNs 回归需在 App 后台／锁屏时来电，从 CallKit 接听并立即回前台，再切回后台。确认 `agent_ready` 后持续存在双向音频，前后台切换不出现启动 `rollback`；真实挂断或系统停用音频后应停止。另检查权限等待或登记在途时挂断，不得因迟到完成重新拉起 PCM；下一通电话仍可接听。


自动测试覆盖慢补充请求、合并请求、晚返回失效及挂断边界。模拟器测试只能验证控制逻辑，不能证明三星蜂窝 PCM 与 iPhone 的真实双向音频已经恢复。
