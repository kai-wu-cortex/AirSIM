# F50 Pro 英国 CMLink / CMHK 对照诊断

2026-11-17，未发布的 MU3356 兼容分支。用户确认英国卡在普通手机可接入 CMHK 5G，能通话和收发短信；此为用户对照结果，不是本工具在普通手机上的实测。

## 设备观察

交换卡槽后，香港卡在逻辑槽 0、英国卡在槽 1；两卡均已加载。香港卡 LTE 正常注册且 IMS 已注册，英国卡可显示 CMHK `45412`，但 ServiceState 仍为 LTE EMERGENCY / OUT_OF_SERVICE，IMS 未注册。两卡无线电电源均开着，未设置 radio power-off reason。用户及运营商允许的制式都包含 NR，因此不能认定为单纯的 5G 开关关闭。

## 有限对照

保持 Wi-Fi、香港卡默认语音/SMS、双卡保持和 AirSIM 配对，依次测试：

1. 英国卡开启数据漫游；仍未正常注册。
2. 指定 CMHK；选网返回 `false`，实际进入手动模式，明确恢复自动后继续。
3. 开启英国卡移动数据；仍未正常注册。
4. 将英国卡临时设为主数据卡，连续 10 次采样仍无服务；香港卡注册和云端在线保持。
5. 英国卡作为主数据卡时再次指定 CMHK；返回 `false`，随后 5 次采样仍无服务。

这些结果不支持“只开数据漫游或改主卡即可修复”。目前更应调查 F50 基带/运营商配置与该卡漫游接入的兼容性，但尚不能定位为具体频段、IMS 配置或网络侧拒绝。Android 注册记录的 `rejectCause=0`、`mRegistrationDeniedReason=null` 未提供明确原因；vendor AT 回读实验因 Binder `bad array lengths` 失败，不能声称已获得网络拒绝码。未修改 IMEI、IMSI、卡片内容、基带或射频配置。

失败对照结束后恢复英国卡自动选网、原数据漫游/数据开关，以及香港卡主数据卡；双卡保持继续启用。最终读回及连通性结果记录在交付总结。没有在本轮拨号或发短信，也没有重启、刷机、安装 AirSIM APK 或部署 Relay。

## 工具与状态

新增 [临时 ADB 诊断工具](../android-standalone/tools/f50-radio/README.md)，独立于 AirSIM APK 和开机服务。JDK 编译、DEX 构建和 MU3356 实机执行通过；以香港卡作为英国卡操作目标的负向保护检查被拒绝。此工具不是英国卡修复包。未新增自动化测试；此次依据是受控实机对照。保留现有本地签名 Apps 140 / iOS 176 挂断修复。

英国卡在 F50 上注册/通话/短信仍未通过，双卡启用不能等同于两张卡都已获运营商服务。
