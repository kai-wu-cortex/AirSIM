# Tailnet 配对与 iOS 导航复查

## 当前范围

基于 `codex/device-test-20261029` 工作树，保留此前未提交修改。本次不是 Release、部署或真机安装。
纯本地模式仍只有基础策略/协议与测试，未完成设置滑块、两端协调和全局 Relay 出站禁用；现有 VoWLAN 模式不能当作该功能的完成版本。

## 用户日志证据

用户导出的 iOS 0.9.8 (147) Verbose 日志共 1200 条本地记录，`agent_events=0`。没有 Android PCM 现场事件。

- 2026-10-29 13:50–13:53 UTC：标记 VPN 直连的 `/api/health` 多次 HTTP 200，约 0.85–1.66 秒。
- 同期 Bonjour 浏览器约每 10 秒重建，并选中 LAN 地址，而用户手动配对地址是 Tailnet 地址。
- 更早出现大量 `PROBE_STALE`，表示成功返回的健康结果被其他探针/网络代际作废。
- 因而不能仅依据“网关不可达”文案认定 Tailscale ACL 拒绝或 PCM 未启动；控制 API 可达也不等于双向音频可用。

## 修改

1. 尚未验证时，保存的 100.64/10 Tailnet 候选不再被同设备 LAN 广播直接覆盖。既有已验证/通话中 LAN 路由保持稳定；探针失败后仍可显式尝试同设备 LAN 候选。RFC1918 DHCP 更新策略保持不变。
2. 同网络代际、同端点的并发探针共享任务。网络代际变更取消旧任务，旧任务结束不能清除新任务。任务独立于发起它的 watchdog，避免发布失败/回退状态取消 watchdog 时连带取消回退验证。
3. 验证期间保持候选稳定，签名、身份检查及旧代际结果拒绝仍执行；没有开放公网地址、修改 VPN ACL 或降级到 Relay。
4. iOS 改为各 Tab 自有导航，移除包围整个 TabView 的外层导航栈，避免压住联系人搜索和最近通话导航栏。短信页保留独立工具栏和导航目的地，详情使用原生 tabBar 隐藏策略。
5. UI 测试使用模拟器专用、临时通讯录数据，不读取个人联系人；正常 App 默认仍创建系统 ContactStore。

## 验证与限制

新增回归曾分别复现 Tailnet 被 LAN 替换、联系人搜索缺失，以及同端点并发触发启动两次探针。第一次完整测试中两个 UI 测试通过，单元测试有一条旧候选策略断言失败；已改成显式 LAN 回退场景，而非把“尚未验证”等同于“已失败”。

最终验证：iOS 27 模拟器串行运行 358 个单元测试、2 个 UI 测试，全部通过（xcodebuild exit 0）。结果 `/tmp/airsim-tunnel-final.xcresult`，日志 `/tmp/airsim-tunnel-final.log`。Release 通用 iOS 未签名构建通过（exit 0），日志 `/tmp/airsim-tunnel-release.log`。`git diff --check` 通过。测试不代表 Android/Agent 全项目测试，也不代表已签名可安装包。

未做真实 Tailscale 隧道或 PCM 双向语音验收，不能宣称用户设备已恢复；当前截图对应的已安装 App 不会因修改本地源码自动更新。

## 真机复测

安装修复构建后，保持三星蜂窝 + Tailscale、iPhone Wi-Fi + Tailscale，使用三星 Tailnet 地址和本次配对端口配对。检查签名健康验证成功，切后台再回前台、断开重连 VPN，确认不会持续停留“正在验证”。随后分别拨出/接听并验证双向语音。

若仍失败，记录时间并手动导出两端新日志（特别是 Android 控制/PCM 网关状态）。不要清除配对密钥、公开配对码或放宽 VPN ACL 来替代排查。
