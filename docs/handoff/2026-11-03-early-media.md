# 接通前运营商语音：客户端与 U30 Air 联调契约

用户要求听到真实运营商接通前语音，保持未接通状态、不提前计时。用户已明确授权通知 U30Air 线程协同设备端；该线程负责 Agent、网关与音频源，本线程只改 AirSIM 客户端。源码实现阶段未操作设备。随后用户明确回复“安装”，授权覆盖安装两端候选及准备临时试听；真实拨号与挂断仍由用户手动执行，不录音、不发布。

## 不能混淆的状态

- `EARLYMEDIA` 是下行媒体指示，不是拒接原因，也不等于 active。
- 只有当前设备／当前通话的真实 active 才进入双向通话、启动接通计时。
- ended 仍按明确身份处理，停止早期音频、等待音及界面；不能等公告播放完再消费已到达的终态。
- 设备只支持旧协议时继续等待音，不开启未经授权的 PCM，也不切到 Relay 重拨。

## 控制接口

复用已配对 Agent 的鉴权 GET `/api/calls/early-media?call_id=<backend ID>`，3 秒超时，新的请求 nonce；不接受服务器提供其他媒体地址。

| 响应 | 客户端行为 |
| --- | --- |
| 200 + 有效签名 grant | 开始或续期只接收音频 |
| 202 | 本通话早期媒体未就绪，2 秒后继续查询 |
| 404 / 409 / 501 | 不支持，停止本次探测，保持原行为 |
| 400 / 401 / 403 / 410，或无效 grant | 停止早期媒体；不据此伪造通话结束 |
| 网络错误 / 其他 5xx | 最多连续 3 次失败，然后停止；不重复拨号 |

协商单轮使用单调时钟，总上限 120 秒。通话结束、被替换、任务取消立即退出；CallKit 停用音频时停止协商，重新激活后可对同一通话再次协商，仍不发送 dial。

200 的 `EarlyMediaGrant` 与 [原客户端协议](2026-11-03-u30-r18-client-call-safety.md) 保持一致：版本 1、明确 Agent / backend call / session、30 秒内有效期、`early_media`、`recvonly`、`s16le-8000-mono`，使用配对密钥和本次 nonce 验证 `AIRSIM-EARLY-MEDIA1` proof。

## PCM 与租约续期

原 PCM 端口使用独立 `AIRSIMEM1` 签名握手；确认前不能发送 PCM，不能降级为双向握手。服务器回复 `AIRSIMREADY`，然后为 8 kHz 单声道 s16le 字节流。

- 客户端不请求麦克风权限、不创建 input node/tap；传输层拒绝 sendPCM。设备端也必须拒绝握手后的客户端上行数据。
- 同一配对身份／通话的续期 GET 保持 session_id，返回新有效期，设备端同步延长该 PCM 会话租约。客户端约在到期前 8 秒续期，同 session 不重建播放器。
- 新授权同时更新线程安全的握手状态，TCP 重连时使用最新有效期；拒绝把授权回退到旧到期点或其他会话。续期返回 202 时立即停止旧早期播放，再等待新授权。
- 如果返回新 session_id，客户端关闭旧连接并重新握手，不将旧授权用于新会话。
- 客户端有独立到期任务，续期请求挂起也不允许越过最后一次有效授权。设备端同样需在到期、真实 active、ended 或身份撤销时关闭早期通道。
- 首个有效 PCM 帧到达时停止本地等待音。收到 grant 或 ACK 本身不证明已经听到公告，不模拟运营商语音。

## iPhone 界面与时长

呼出未接通显示“正在呼叫 · 尚未接通”；收到早期 PCM 后显示“运营商语音 · 尚未接通”，只接收状态用蓝色区分。此阶段保留扬声器和挂断，不展示录音、静音／DTMF 及接通时长。只有真实 active 开始计时，首次 active 的观察时刻作为本次 UI 时长起点，不把此前拨号／公告等待时间计入。重复 active 不重置时钟。

真实 active 后撤销早期会话，沿原有权限和 CallKit 音频路径启动双向通话；旧早期任务不得停止新通话音频。
