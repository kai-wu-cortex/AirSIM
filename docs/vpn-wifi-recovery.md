# VPN 与 Wi-Fi 切换后的 VoWLAN 恢复

## 问题与证据范围

用户报告：iPhone 在 5G + VPN 下使用安卓的 192.x 地址正常，关闭 VPN 并连接 Wi-Fi 后，状态在离线和就绪之间反复切换。

代码检查发现：网络恢复只重启 AppModel 的轮询，没有同步重建 LocalDeviceDirectory 的设备订阅。另外，同一 IP 重新完成身份认证时会复用旧订阅；旧网络长轮询延迟返回的失败仍可把新认证的设备标成离线。

这是可在测试中模拟的时序缺陷。尚未取得本次真机切换日志，不能认定它解释所有反复断连；尤其需要确认切换后的 Wi-Fi 与安卓实际处于同一可达网络，而非另一个使用相同 192.168.x 网段的网络。

## 本次修改

- 同一设备、同一地址重新认证成功后，取消旧长轮询，并从初始事件游标获取新快照。
- VoWLAN 网络恢复成功后，同步取消设备目录中的旧订阅和过期认证，重新验证各设备身份，然后恢复订阅。Wi-Fi 和蜂窝/VPN 恢复均使用该流程。
- 被取消的认证请求不能再将设备标成离线。
- 保留设备身份、配对密钥与通话 epoch；正在通话时仍遵守原有路由固定策略。
- 不放宽私网检查或身份认证，不添加 Relay 回退。

## 回归测试

`LocalDeviceDirectoryTests` 新增两个用例：同地址重新认证后旧 VPN 请求失败、网络恢复重新认证后旧订阅失败。测试传输层故意不响应取消，以验证迟到失败不会覆盖新状态。

同时验证前台恢复、无效身份凭据不能恢复在线、重复网络通知不使恢复任务失效、通话模式约束。

## 真机验收步骤

1. 使用包含本次修复的 iOS 构建，保留原配对。安卓与目标 Wi-Fi 在同一可达局域网。
2. iPhone 关闭 Wi-Fi，使用 5G + VPN，通过已配对的安卓 192.x 地址确认可用。
3. 关闭 VPN，连接目标 Wi-Fi，等待重新认证；观察至少 2 分钟，检查是否反复离线/就绪。
4. 反向切换回 5G + VPN，重复 3 次；分别在纯本地模式开启和关闭时测试。
5. 恢复后测试一次拨号、接听和双向音频。通话中的跨网络无缝切换不属于本次保证范围。
6. 若仍异常，导出覆盖切换前后时间段的 iOS Verbose 日志和安卓日志，记录切换时间、Wi-Fi 网段及 VPN 类型；分享前移除密钥、配对码和完整电话号码。
