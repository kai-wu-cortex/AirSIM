# 短信删除与音频 Watchdog（候选 build 84）

本地候选版，未安装、发布或上传 TestFlight。继承 build 83 的手动地址配对，不需要更新 Relay 或 Linux Agent。

## iOS 短信删除

- 短信列表左滑删除整个会话；左上角菜单“选择会话”后可多选，再从菜单删除所选。
- 会话内长按气泡删除单条。删除前均确认。
- 删除仅作用于本 iPhone 的 AirSIM 记录，不删除安卓系统短信，也不调用模块的 clear-module 接口。
- 确认窗口打开后新收到的短信不属于已选删除集合。
- `messages.json` 原子保存短信和 SHA-256 删除标记，兼容读取旧版数组。删除标记不保留号码／正文。后台推送、旧同步回包、重启和等待回执期间的删除都需重新应用标记。
- 删除有 `delivery_id` 的短信时以交付 ID 为准；内容相同、同一秒收到但 ID 不同的短信互不影响。真正删除旧版无 ID 短信时另存旧格式标记，防止 Agent 升级补 ID 后回流。旧 Agent 没有 ID 时只能以号码／正文／秒级时间／方向的哈希识别，无法区分完全相同的旧格式重复记录；磁盘／内存合并使用相同秒级精度避免重复，后台旧快照也不能清掉新收件。
- 写入失败保留原有 UI 记录并提示；文件损坏时不覆盖已有文件或删除标记。勿用不认识新封装格式的旧版 App 覆盖本机数据做回退。

## 安卓 Watchdog

不增加独立前台服务，复用当前 InCallService 与已授权 Shizuku。每 2 秒检查一次，探测不在 UI 或 PCM 收发线程执行。只有当前唯一的原生通话 ID 与已确认的远程控制身份、已就绪 PCM 所有者相符才允许修复；PCM 握手本身不能取得任意通话。多通话、旧会话残留、已结束或无法确认的归属不执行修复。

身份来源为 VoWLAN 的 DirectCallOwnership 租约、VoBLE 的已确认 Android call ID、Standalone 云端会话的 androidID。旧 AVF 云端若没有经过 APK 的已确认媒体身份，不推测归属、不会因此启用自动修复。显式“安卓静音”模式原有行为不变。

探测读取系统 voice-call stream 的静音标志、音量索引、音频 mode、speaker 标志及 shell PCM 进程存活状态，同时记录传输种类。它不是麦克风监听，也不能证明物理听筒／扬声器真的无声，日志始终标注 `acoustic_check=unavailable`。

连续两次发现未静音、PCM 已运行才触发受控步骤：

1. 重新应用原有、可校验且保留初始快照的静音控制。
2. 请求 InCallService 重新评估远程音频策略，再应用静音。
3. 再次应用策略；特权连接不可用时请求重新绑定原 Shizuku 服务、重放当前意图。

每步都有后置检测；失败为 unknown／unresolved，不是成功。每个会话世代最多三次动作，间隔至少 15 秒，成功一次不重置总预算。探测异常时只尝试有预算的重新绑定，不盲目更改音量。结束、切换所有者或出现另一通电话立即使旧世代失效。原有挂断恢复仍由保留的音量／静音快照及恢复重试执行。

不执行外部任意 shell 脚本，不重启系统音频服务或 PCM，不强切本次通话链路、不自动挂断。厂商 AudioManager 操作通过单个 in-flight 有界工作器执行，超时不能取消已进入系统的操作；忙碌时不排队堆积，保留快照，待系统恢复后重试恢复。音频锁与 PCM 生命周期锁隔离。

## TXT 导出

安卓“Debug 诊断 → 保存音频 Watchdog TXT”打开系统保存窗口，生成真实 UTF-8 `.txt` 文件。内容含 App／Android／机型、时间、匿名世代、采样、修复步骤、耗时、异常类型及复检结果。

Watchdog 的脱敏 `VERBOSE` 快照自动本机记录，不要求先打开普通 Debug。复用两个各约 512 KiB 的轮换日志；长时间测试会淘汰最旧部分。普通 Debug 仍控制其他详细日志。文件不会自动上传；导出前可清空日志再复现。不得记录通话 PCM、短信正文、真实号码、Push token、配对或 Relay 密钥。

## 验收边界

自动测试覆盖旧数据迁移、单条／批量删除、防回流、不同 delivery ID 隔离、存储失败、普通通话跳过、精确媒体所有者、旧租约清理、静音漂移后复检、冷却／预算、无 PCM 与未知状态、世代失效和厂商接口卡顿后恢复。构建和测试不能代替双真机来电、接听、挂断、不同厂商路由与实际扬声器验收。

本地 iOS 128 项回归、Android Standalone 完整测试（含 47 项 PCM 桥检查）、真实 TCP PCM 集成与真实线程卡顿／恢复测试通过。候选安装包在 `iOS/build/candidate84/`；IPA 未签名，需重签，不是可直接安装的 TestFlight 包。未执行真机安装、Git 提交／推送、Release 或 TestFlight 发布。
