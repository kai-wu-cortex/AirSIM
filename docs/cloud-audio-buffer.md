# 云端音频缓冲

入口：iPhone 设置 → 连接与设备 → 通话连接方式 → 云端音频。云端 Relay 页面也提供相同设置。

| 选项 | 行为 |
| --- | --- |
| 自动（默认） | 保留原策略：从 80 ms 起，iPhone 目标最多 240 ms、Android 最多 200 ms，接收队列上限 240 ms。 |
| 稳定优先 | 从 240 ms 起，根据到达抖动和缺帧上调，目标最多 720 ms；稳定后回落至 240 ms。队列硬上限 760 ms。 |
| 手动 | 固定目标可选 240、480、720、960 ms，默认选择 720 ms；队列硬上限为目标加 40 ms。 |

每帧为 20 ms。720 ms 表示先积攒 36 帧再播放，不是端到端延迟保证；iPhone 播放器还可另排 40 ms。更大的缓冲能吸收短暂到达间隔，代价是对话等待增加。持续断网、带宽不足和 TCP 队头阻塞不能靠缓冲根治。当前策略在耗尽后重新预缓冲，不通过无限重复旧语音填补缺口。

设置持久保存在 iPhone，仅影响云端 PCM 接收播放；不影响 VoWLAN、VoBLE、PushKit、CallKit 或 Relay 转发时机。通话期间禁止修改，新通话读取快照；同一通话的网络重连与音频路由恢复沿用该快照。结束通话清空缓冲。发送侧仍受 240 ms 队列与 250 ms 过期丢弃规则约束，不在麦克风采集端增加 720 ms 等待。

## 新旧 Agent 协同

既有认证媒体 WebSocket 的 `answer` 控制帧携带可选字段：

```json
{
  "audio_buffer_version": 1,
  "audio_buffer_mode": "manual",
  "audio_buffer_ms": 720
}
```

必须连同既有 `call_id`、`call_uuid`、`generation`、`command_id` 和 `trace_id` 发送，不引入额外拨号意图。Android 只有在认证媒体连接和完整通话身份校验通过后，才接受本通话首次 answer 的策略；重放不能反复重置播放队列。模式只接受 automatic/stable/manual，手动毫秒值只接受上述四档，未知版本或非法参数回退自动。Android 正在接收播放时采用同一选择；接通前只允许原有单向下行，不因缓冲配置开启麦克风上行或提前 active/计时。

当前 Cloudflare Worker 与 ECS 自托管的媒体转发会保留这些可选字段，服务端无需新增延迟或修改业务代码。旧 Android、U30Air 与 AVF Agent 可以忽略这些字段，iPhone 接收侧仍生效，但不能因此声称旧 Agent 的接收缓冲也同步改变。U30Air/AVF 若要双向应用，应按同样的身份约束和有界队列适配；本轮未修改它们。

## 验证与实机清单

自动化覆盖默认值和非法配置、720 ms 预缓冲、400 ms 到达空档、积压硬上限、稳定模式回落、重置不播放旧帧、发送侧不被延迟、真实 Android PCM pump 的预缓冲门槛，以及 Relay 可选字段透传。所有音频均为合成数据。

2026-11-08 验证结果：iOS 最终界面构建通过；原生 Xcode 定向回归 29 项通过（含新增缓冲 5 项、音频图与云端生命周期）。Android 全套脚本测试及 Standalone Debug 构建通过；Worker 80 项测试通过。首次 MCP 全套 iOS 测试在启动测试进程时超时，未计为通过；随后使用原生命令完成上述定向回归。

真机建议在同一个 Relay 下分别测试三档策略：

1. 先选择自动并完成一通双向通话，记录卡顿和对话等待。
2. 下一通改稳定优先，对比网络抖动期间的连续性。
3. 下一通改手动 720 ms，检查声音更平稳与延迟增大的取舍。
4. 每档检查运营商接通前语音、接通前不计时、扬声器/耳机切换、挂断后无残留语音。
5. 重连后检查缓冲仍采用本通话选择；下一通切回自动，确认没有沿用 720 ms。
6. 旧 Agent 单独验证只有 iPhone 播放侧改变，不能把双向未适配误判为设置失效。

源码实现及模拟测试不代表真实弱网音质已验收；真实电话由用户手动测试。
