## 主要变化

- Android 状态页现在读取真实 Agent、Push/Relay、VoWLAN、PCM 与 Shizuku 状态，并提供可展开的脱敏诊断信息。
- 拨号、接听、拒接、挂断和 DTMF 在执行前明确检查默认电话角色，避免命令落到 DJOneHub 或其他电话 App。
- VoWLAN 就绪状态同时要求 Agent 与 PCM 握手完成，减少“界面显示就绪但语音通道未建立”的误判。
- Android Debug 页面增加过滤、错误突出和更完整的最近事件展示。
- iOS 去电路由加强三星 VoWLAN/云端选择与失败边界。
- AirSIM Relay 已迁移到独立的 `https://airsim-push.remotepilot.site`；DJOneHub 继续使用 `https://push.remotepilot.site`。

## Android 安装

1. 下载并核对 `AirSIM-Android-0.9.0.apk` 的 SHA-256。
2. 如果设备上安装的是旧 debug 签名包，先记录配对信息并卸载旧包。
3. 安装 APK，将 AirSIM 设为三星默认电话 App。
4. 启动 Shizuku，向 AirSIM 授权，然后重新连接 AVF Agent。
5. 分别验证拨号、接听、挂断、短信、VoWLAN 和双向 PCM。

## iOS IPA 重签

公开 IPA 是 unsigned 构建，不包含开发证书、provisioning profile 或设备 UDID，不能直接安装。重签时必须同时处理：

- 主 App：把 `com.example.airsim` 换成自己控制的 Bundle ID。
- Watch App：主 Bundle ID 加 `.watchkitapp`。
- Live Activity Extension：主 Bundle ID 加 `.liveactivity`。
- 使用自己的 Apple Developer Team、证书和 provisioning profiles 签署主 App、Watch App 与 Extension。
- 在自己的 Relay 中把 `ALLOWED_BUNDLE_ID` 设为新的主 Bundle ID，并配置对应 APNs `.p8`。
- 设置自己的 `AIRSIM_PUSH_RELAY_URL`；维护者 Relay 只接受 `com.eric3u.airsim`。

完成重签后，再在实体 iPhone/Apple Watch 验证 PushKit、CallKit、APNs sandbox/production、后台来电和云端 PCM。unsigned IPA 构建成功不代表这些真机链路已经通过。
