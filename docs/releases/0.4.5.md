# AirSIM AVF Agent 0.4.5-1

本版修复动态 AVF 私网下 Android 宿主访问 Agent 返回 HTTP 403、导致 iPhone 配对失败的问题。Agent 现在可使用可信的本地 socket 地址识别 Android–AVF 同网段连接；公网和无关局域网仍被拒绝。错误提示从“只允许 USB 本地网络访问”改为“只允许 AVF 私网访问”。

## 一次性签名密钥迁移

旧 v0.4.4 发行私钥未留存，现有 `airsim-installerd` 不信任新签名。**已安装 `0.4.4-1` 的设备不能直接在 Android App 内点“更新到最新版”。**先在原 AVF Linux Terminal 执行：

```sh
curl -fsSL --connect-timeout 10 --max-time 90 --retry 2 --proto =https --proto-redir =https --tlsv1.2 -o /tmp/airsim-rotate-v0.4.5.sh https://github.com/kai-wu-cortex/AirSIM/releases/download/v0.4.5/rotate-avf-key.sh
printf '%s  %s\n' '9ae6b8c69d5d9877638a50240282a67d06b73d807dba444c816c5efb9c5ec04d' /tmp/airsim-rotate-v0.4.5.sh | sha256sum -c - && sudo sh /tmp/airsim-rotate-v0.4.5.sh
```

脚本仅接受已安装 `0.4.4-1` 且保留包与 v0.4.4 Release 完全一致的 AVF；下载、签名、包名、架构、Debian 依赖任一预检失败均不安装。它保留旧包为 `previous.deb`，更新后验证 AirSIM Agent 与 installer；失败时尝试回滚。不会更改 DJOneHub 的 `7575` 服务、AirSIM 控制 token、Push 配置或 AVF 数据。旧私钥丢失，无法用旧密钥交叉签名此脚本；请核对 GitHub 域名、以下脚本摘要与新公钥指纹。

- 新发行公钥（Ed25519 原始 32 字节，Base64）：`QQPJXjO2mcx13qhv74lXen8ytjJZ2hMCz+ERlz6w5qg=`
- 新发行公钥 DER SHA-256：`4c39d5afdca2dddd8d22c0a5e02da18e7f07db789baac04bce4cfcd57491b3f4`
- 迁移脚本 SHA-256：`9ae6b8c69d5d9877638a50240282a67d06b73d807dba444c816c5efb9c5ec04d`
- Debian 包 SHA-256：`037d5c4e37898420f8ffaebae18519d4cf25910e5c81c3e4d4a7f87364cf6648`

首次安装且没有旧 AirSIM Agent 的 AVF 使用同一 Release 中的 `install-avf.sh`，**不是** `rotate-avf-key.sh`。迁移后可从 App 的安装管理页面使用新密钥签名的后续更新。

## 验收

1. `dpkg-query -W airsim-avf-agent` 显示 `0.4.5-1`，`airsim-agent` 和 `airsim-installerd` 均在运行。
2. 三星通过当前动态 AVF 私网访问 `8575/api/health` 返回 HTTP 200，且 `product=airsim`、`version=0.4.5`；`8576` 仍要求控制 token。
3. 使用 iPhone 与三星再次配对，确认不再收到 HTTP 403，再单独验证 Relay、电话和 PCM；健康检查成功不等于通话链路全部验收。

完整排障与回滚说明见 [AVF 安装指南](../AVF_INSTALL_GUIDE.md)。
