# AirSIM Apps v0.9.2

AirSIM Apps v0.9.2 首次发布 Android Standalone APK：AVF Agent 的 Relay 心跳、云端命令、设备身份、状态 API 与媒体编排已合并进 Android 前台服务。新安装不再需要 Linux Terminal、Debian、AVF 私网、`8575/8576` 或 `airsim-installerd`。旧 AVF Linux Agent [v0.4.5](https://github.com/kai-wu-cortex/AirSIM/releases/tag/v0.4.5) 仍保留用于兼容与回退。

## 主要变化

- Android 内置 Agent 负责 Relay 注册、30 秒心跳、WebSocket/HTTP 命令、设备状态、Push 与单路云端 PCM 编排；状态读取改为进程内接口。
- Android Bridge 将 Agent 的 `send_sms` 命令与 Telecom 通话操作分流，避免错误地进入通话 ID 校验并出现 `active call id mismatch`。
- 发送短信前检查系统权限、短信功能及默认短信 SIM；使用 Android 系统短信服务分段发送，等待每段的系统发送回执后才向 Agent 报告结果。回执不等于收件人已收到；超时后应先核对，避免重复发送。
- 小米 HyperOS 无法打开默认电话角色选择页时，在用户已授权 Shizuku 后由 APK 自动完成角色设置；启动时清理遗留的旧 PCM Bridge 进程。
- 非三星 Android 通过系统 `TYPE_TELEPHONY` 音频设备选择通话上下行；三星继续优先使用语音 TX 路由。小米 HyperOS 真机已验证通话声音在 iPhone 播放。
- iOS PCM 每次 TCP 重连都会生成新的握手 nonce，避免服务端把重连误判为重放并出现 `cycle failed`。
- iOS 短信通知接受 Agent 的纳秒精度时间戳，使用 `delivery_id` 对齐推送与本地同步副本。点击短信通知可进入发件人会话，冷启动也会保留导航请求。
- 本次未新增三星系统短信收件广播采集；iOS 通知链路的前提仍是 Android/Agent 已生成并上传相应短信事件。不要把发信验收视为完整双向短信验收。

## Android 更新

1. 下载 `AirSIM-Android-Standalone-0.9.2.apk`，核对本页 SHA-256 和发布证书 SHA-256。
2. Standalone 使用独立包名 `com.airsim.phonecontrol.standalone`，可与旧 AVF 版并存，但不会继承旧包的配对资料；安装前先记录 Relay、设备 ID 和配对信息。
3. 启动 Shizuku 并授权 AirSIM Standalone，授予电话、短信和通知权限，再将它设为默认电话 App。HyperOS 系统页面不可用时回到 App，让它自动完成设置。
4. 同一时间只让一个 AirSIM 包持有默认电话角色和 PCM 会话。Standalone 验证完成后可停止 AVF Agent；清除 AVF/Debian 数据不是安装步骤。
5. 在 iPhone 分别验证拨号、接听、挂断、双向音频和短信；短信系统回执后仍需由收件方确认实际收到。

## iOS IPA 重签

公开 IPA 是 unsigned 构建，不包含开发证书、provisioning profile 或设备 UDID，不能直接安装。使用自己的 Apple Developer Team 为主 App、Watch App 与 Live Activity Extension 分别配置 Bundle ID、签名和 provisioning profile，并让自己的 Relay 的 `ALLOWED_BUNDLE_ID`、APNs topic 与主 App 一致。完整步骤见 [iOS README](../../iOS/README.md)。

## 安全边界

本项目仅限许可证允许的非商业用途。APK/IPA 不包含 APNs 私钥、Dashboard token、Cloudflare token、AVF 控制 token、Android 发布私钥或 Apple 签名身份。AirSIM 不能替代系统紧急呼叫能力。
