# 可选：NAS / 软路由自建域名 TLS 直连

已在局域网完成 VoWLAN 配对的 iPhone，可以为每台安卓配置一个自建域名入口。默认关闭；这仍是现有 VoWLAN 控制与 PCM 协议的另一条传输路径，不是新增云端 Relay，也不需要修改 Android 配对协议。iPhone 与 Watch 客户端需使用包含此功能的构建。

## 网络结构

```text
iPhone（Wi-Fi / 蜂窝）
    │ DDNS 域名，系统校验证书
    ├── HTTPS 控制端口 ─┐
    └── TLS 音频端口 ──┤
                       ▼
              软路由端口映射 / IPv6 放行
                       ▼
              NAS 上的 TLS TCP 网关
                ├── TCP → 安卓局域网控制端口
                └── TCP → 安卓局域网 PCM 端口
```

NAS 终止 TLS，在可信局域网内以自己的私网源地址连接安卓。安卓继续执行现有来源地址检查、HMAC、时间戳、nonce、路由白名单及 PCM 单会话限制。不要开启透明源地址保留或 PROXY protocol：原版安卓不解析 PROXY 头，公网来源也会被来源策略拒绝。配对端口、AVF `8575/8576`、Shell PCM `7580` 不对公网开放。

用户需具备可入站公网 IPv4（映射两个 TCP 端口），或 NAS 可入站 IPv6（放行两个 TCP 端口）。DDNS 的 A/AAAA 应指向实际可达地址；若两者都发布，两者都应配置正确。CGNAT 下仅配置 DDNS 不能获得公网入站能力。没有可用 IPv6 的客户端不能连接只有 AAAA 的入口。

## 网关示例：stunnel

将安卓固定为 DHCP 保留地址，例如 `192.168.1.50`。NAS 以 ACME / DNS 验证等方式为 `phone.example.com` 申请并自动续期可信证书。以下是 **stunnel 服务端配置片段**，示例中的地址、端口和证书路径需要替换：

```ini
foreground = yes
client = no
sslVersionMin = TLSv1.2
cert = /certs/phone.example.com/fullchain.pem
key = /certs/phone.example.com/privkey.pem

[airsim-control]
accept = 0.0.0.0:8443
connect = 192.168.1.50:7592
TIMEOUTidle = 120

[airsim-pcm]
accept = 0.0.0.0:17593
connect = 192.168.1.50:7593
TIMEOUTidle = 120
```

这两个服务都使用原始 TCP TLS 转发。控制连接里的 HTTP 方法、路径、正文及 `X-AirSIM-VoWLAN-*` 头原样到达安卓；音频连接里的 `AIRSIMVWL1` 认证握手和后续 PCM 字节同样原样转发。无需在 NAS 保存或配置 AirSIM 配对密钥。NAS 是受信任的 TLS 终止点，能接触解密后的控制和音频流。

示例使用 IPv4 监听；IPv6 部署应按 NAS 的 stunnel 版本配置 IPv6 监听地址，并验证对应防火墙规则。证书续期后按 NAS 的服务管理方式重新加载 stunnel。可使用 nginx stream / HAProxy 等提供等效的两路 TCP TLS 转发；只有常见的 HTTP 网页反向代理不能承载 PCM 音频。

安卓当前通常使用控制 `7592`、PCM `7593`；端口冲突时会选择其他端口，因此必须核对安卓实际网关端口。可以在 iOS Verbose 的 VoWLAN 发现事件中核对 `control_port` 与 `pcm_port`。这些不是一次性配对端口。安卓重启后若端口变化，更新 NAS 后端端口。路由器可以把公网 `443` 映射到 NAS `8443`、公网 `17593` 映射到 NAS `17593`；iOS 填写的是公网端口。

若控制与 PCM 放在不同端口，必须确保两路都转发到同一台安卓。iOS 保存时验证控制入口与设备身份；音频端口只做格式校验，实际 TLS / PCM 认证在通话建立时执行。不要把控制验证成功当作双向声音已验收。

## iOS 设置

1. 在局域网完成现有 VoWLAN 配对，并确认可以通话。只有蓝牙配对、没有该设备 VoWLAN 密钥时无法启用此功能。
2. 在「设置 → 三星连接 → 自建域名直连（可选）」选择已配对安卓。
3. 打开启用开关，填写 DDNS 域名、HTTPS 控制端口、TLS 音频端口。域名不带 `https://`、路径、用户名或端口；国际化域名先转换成 ASCII / Punycode。
4. 点击「验证并保存」。iOS 使用系统 DNS 路由和正常 TLS 信任校验，向 `/v1/health` 发起现有 HMAC 请求；只有目标 `agent_id` 与已配对设备一致、且返回有效的 nonce 绑定身份签名后才保存。验证失败保留原配置。
5. 选择 VoWLAN、自动或本地双通道模式。局域网优先，不可达时尝试同一设备已保存的远程入口。纯云端或纯蓝牙模式不因配置该入口而自动启用 VoWLAN。
6. 关闭 Wi-Fi，以蜂窝网络验证控制、短信与双向通话。局域网不支持 NAT 回流时，首次验证可用蜂窝网络；配置不依赖公网配对。

关闭开关并保存会删除该设备的远程路由，保留局域网路由与配对密钥；删除设备会一起清除两类路由。更改某台设备的远程配置不会更改默认选中设备。验证过程中删除设备、关闭配置、重新配对或取消页面任务，不应由迟到响应恢复旧配置。

## 兼容与行为边界

- 旧版手动路由和配对历史缺少 TLS 字段时仍按原来的私网 TCP 解释。普通手动配对仍不接受公网 IP、域名或 URL；不会把公网地址加入私网白名单。
- HTTPS 与 PCM TLS 使用 Network.framework 默认的证书链和域名验证，不提供忽略证书错误的开关，也不在 TLS 错误后降级成公网明文。
- 远程入口使用该设备独立的 Keychain 凭据，不借用其他设备或全局旧密钥。自建配置不写入 Android 或 Relay，不上传域名、证书或配对密钥。
- 每轮失败探测对每个候选地址最多尝试一次，且只在同一设备内选择地址。已建立的通话保持原控制与媒体路径，通话中禁止修改配置；网络断开不静默把通话交给另一个入口或另一台设备。
- Wi-Fi 恢复时复用已有发现与认证恢复机制。地址保存不等于在线，重连仍检查身份；DNS / DDNS 更新通过新连接时的系统解析生效，不缓存固定公网 IP。
- Watch 媒体参数新增可选 `pcm_tls`。新 Watch 客户端用 TLS 连接域名；无标记的旧私网参数继续按原样工作。旧 Watch 客户端拒绝域名参数，需要随 iPhone 更新，不会将其作为明文域名连接。Watch 必须自身能访问该公网入口，不能由 iPhone 配对成功推断 Watch 音频可用。
- 此功能不新增 APNs / PushKit 推送，不绕过 iOS 挂起限制。后台来电唤醒和短信通知仍按现有云端/蓝牙机制工作；不能把前台直连可用视为锁屏持续收听来电。

## 验证

自动化回归覆盖旧路由解码、TLS 地址与端口边界、局域网/远程记录共存及删除、同设备有限次回退、控制身份验证、TLS 失败不保存、修改时保持设备绑定、通话保护、迟到验证取消，以及 iPhone / Watch 的 TLS 媒体参数。

构建与 XCTest 按 `iOS/README.md` 执行。发布前还需用实际 NAS、软路由、安卓、iPhone 和 Watch 验证：首次局域网配对；公网 IPv4/IPv6；证书过期/不匹配；双向音频与短信；回到局域网；DDNS 地址更新；安卓重启端口变化；网关断开；通话中切网；关闭配置和删除设备后的重启；后台与锁屏行为。模拟器与协议测试不能代替这些实机结果。
