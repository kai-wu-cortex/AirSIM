# 试验性：NAS / 软路由自建域名 TLS 直连

> 本功能为试验性功能，包含公网域名首次配对与 TLS 直连。自动化测试已通过，真实公网配对及双向音频仍待真机验收。

iPhone 可以通过 HTTPS 域名完成首次加密配对，也可以为已在私网配对的安卓添加自建域名入口。该入口需用户主动配置；这仍是现有 VoWLAN 控制与 PCM 协议的另一条传输路径，不是新增云端 Relay，也不需要修改 Android 配对协议。iPhone 与 Watch 客户端需使用包含此功能的构建。

## 网络结构

```text
iPhone（Wi-Fi / 蜂窝）
    │ DDNS 域名，系统校验证书
    ├── HTTPS 配对端口 ─┐（临时开启）
    ├── HTTPS 控制端口 ─┤
    └── TLS 音频端口 ──┤
                       ▼
              软路由端口映射 / IPv6 放行
                       ▼
              NAS 上的 TLS TCP 网关
                ├── TCP → 安卓本次随机配对端口（临时）
                ├── TCP → 安卓局域网控制端口
                └── TCP → 安卓局域网 PCM 端口
```

NAS 终止 TLS，在可信局域网内以自己的私网源地址连接安卓。安卓继续执行现有来源地址检查、HMAC、时间戳、nonce、路由白名单及 PCM 单会话限制。不要开启透明源地址保留或 PROXY protocol：原版安卓不解析 PROXY 头，公网来源也会被来源策略拒绝。不得直接向公网映射安卓明文配对端口、AVF `8575/8576` 或 Shell PCM `7580`。首次公网配对仅通过临时的、有效证书保护的 HTTPS 入口转发到配对窗口。配对结束后关闭这一入口。

用户需具备可入站公网 IPv4（日常映射两个 TCP 端口，首次配对临时增加一个），或 NAS 可入站 IPv6（放行相应 TCP 端口）。DDNS 的 A/AAAA 应指向实际可达地址；若两者都发布，两者都应配置正确。CGNAT 下仅配置 DDNS 不能获得公网入站能力。没有可用 IPv6 的客户端不能连接只有 AAAA 的入口。

## 网关示例：stunnel

将安卓固定为 DHCP 保留地址，例如 `192.168.1.50`。NAS 以 ACME / DNS 验证等方式为 `phone.example.com` 申请并自动续期可信证书。以下是 **stunnel 服务端配置片段**，示例中的地址、端口和证书路径需要替换：

```ini
foreground = yes
client = no
sslVersionMin = TLSv1.2
cert = /certs/phone.example.com/fullchain.pem
key = /certs/phone.example.com/privkey.pem

; 仅在首次配对期间启用；45945 必须替换为安卓当前窗口显示的端口
[airsim-pairing]
accept = 0.0.0.0:9443
connect = 192.168.1.50:45945
TIMEOUTidle = 15

[airsim-control]
accept = 0.0.0.0:8443
connect = 192.168.1.50:7592
TIMEOUTidle = 120

[airsim-pcm]
accept = 0.0.0.0:17593
connect = 192.168.1.50:7593
TIMEOUTidle = 120
```

三个服务均使用 TCP TLS 转发。临时配对服务透传 `/pair/v1/info` 和 `/pair/v1/claim`，保留原有六位码、加密注册、窗口有效期与失败次数限制。控制连接里的 HTTP 方法、路径、正文及 `X-AirSIM-VoWLAN-*` 头原样到达安卓；音频连接里的 `AIRSIMVWL1` 认证握手和后续 PCM 字节同样原样转发。无需在 NAS 保存或配置 AirSIM 配对密钥。NAS 是受信任的 TLS 终止点，能接触解密后的控制和音频流。

示例使用 IPv4 监听；IPv6 部署应按 NAS 的 stunnel 版本配置 IPv6 监听地址，并验证对应防火墙规则。证书续期后按 NAS 的服务管理方式重新加载 stunnel。可使用 nginx stream / HAProxy 等提供等效的两路 TCP TLS 转发；只有常见的 HTTP 网页反向代理不能承载 PCM 音频。普通 Cloudflare 网页代理也不提供此原始 PCM TCP 转发；使用 DNS-only 解析或明确支持原始 TCP TLS 的服务。

安卓当前通常使用控制 `7592`、PCM `7593`；端口冲突时会选择其他端口，因此必须核对安卓实际网关端口。可以在 iOS Verbose 的 VoWLAN 发现事件中核对 `control_port` 与 `pcm_port`。这些不是一次性配对端口。安卓重启后若端口变化，更新 NAS 后端端口。路由器可以把公网 `443` 映射到 NAS `8443`、公网 `17593` 映射到 NAS `17593`；iOS 填写的是公网端口。

若控制与 PCM 放在不同端口，必须确保两路都转发到同一台安卓。iOS 保存时验证控制入口与设备身份；音频端口只做格式校验，实际 TLS / PCM 认证在通话建立时执行。不要把控制验证成功当作双向声音已验收。

## App 内使用教程

在「配对安卓手机 → 公网域名」及「自建域名直连（试验性）」页面点击「使用教程」，可打开原生帮助面板。面板支持半屏／全屏阅读，分别说明首次配对与已配对设备的操作，包含端口对应关系、可复制的 stunnel 示例及常见问题。点击底部「返回配置」回到原表单；查看教程或切换教程场景不会改写配对参数。

## 首次在公网域名配对

1. 按上例配置控制与音频入口，并检查公网 DNS、端口放行和有效证书。TLS 网关必须能够从受信任的私网访问安卓；此功能不会自动建立 NAT 穿透。
2. 安卓 AirSIM 点击「开始一次性配对」。将网关临时配对服务的后端端口改为安卓当前显示的随机端口，重新加载网关。新窗口端口可能变化，需同步更新；不要把验证码写进配置。
3. iPhone 打开「设置 → 安卓连接 → 配对安卓手机 → 公网域名」。填写 `phone.example.com`、HTTPS 配对端口 `9443`、HTTPS 控制端口 `8443`、TLS 音频端口 `17593` 和安卓本次六位码。若路由器将公网 `443` 映射到 NAS `8443`，控制端口应填写 `443`。
4. 域名不带 `https://`、路径、用户名或端口；国际化域名先转换为 ASCII / Punycode。三个字段填写的是网关对外端口，不是安卓私网端口。
5. 点击「连接并加密配对」。iOS 先完成 HTTPS 证书验证和现有加密注册，再校验安卓返回的设备身份及内部端口签名；外部端口映射不会绕过签名。接着用该设备独立密钥验证 HTTPS `/v1/health` 的 nonce 绑定签名，通过后保存域名路由。
6. 如果显示「加密配对成功，但公网控制入口尚未通过设备身份验证」，配对密钥已保留，域名路由未保存。修正网关控制转发后，在「自建域名直连」选择该设备重新验证，不要把此提示当作可通话。
7. 选中设备，使用 VoWLAN、自动或 VoWLAN+VoBLE 模式。测试短信和双向语音后，关闭网关的临时配对入口。控制验证不代表音频端口已通过验收。

「仅本次配对不写入云端」开启时只写入本地凭据；纯本地模式继续禁止 Relay。公网域名只是用户配置的直接 TLS 通道，不自动开启云端模式或后台推送。

## 已配对设备添加或修改域名

1. 已通过私网或上述公网入口完成 VoWLAN 配对的设备，可在「设置 → 安卓连接 → 自建域名直连（试验性）」中选择。只有蓝牙配对而没有该设备 VoWLAN 密钥时，需先完成 VoWLAN 配对。
2. 打开启用开关，填写域名、HTTPS 控制端口和 TLS 音频端口，点击「验证并保存」。只有证书、目标 `agent_id` 与 nonce 绑定身份签名均验证成功才保存；失败保留原配置。
3. 局域网优先，不可达时尝试同一设备已保存的远程入口。纯云端或纯蓝牙模式不会因为配置域名自动启用 VoWLAN。通话途中保持原路径。
4. 关闭 Wi-Fi，以蜂窝网络验证短信和双向通话。局域网不支持 NAT 回流时，可用蜂窝网络验证公网入口。

关闭开关并保存会删除该设备的远程路由，保留局域网路由与配对密钥；删除设备会一起清除两类路由。更改某台设备的远程配置不会更改默认选中设备。验证过程中删除设备、关闭配置、重新配对或取消页面任务，不应由迟到响应恢复旧配置。

## 兼容与行为边界

- 旧版手动路由和配对历史缺少 TLS 字段时仍按原来的私网 TCP 解释。「私网 IP」配对仍不接受公网 IP、域名或 URL；「公网域名」入口仅接受带可信 TLS 的 DNS 域名；不会把公网地址加入私网白名单。
- HTTPS 与 PCM TLS 使用 Network.framework 默认的证书链和域名验证，不提供忽略证书错误的开关，也不在 TLS 错误后降级成公网明文。
- 远程入口使用该设备独立的 Keychain 凭据，不借用其他设备或全局旧密钥。自建配置不写入 Android 或 Relay，不上传域名、证书或配对密钥。
- 每轮失败探测对每个候选地址最多尝试一次，且只在同一设备内选择地址。已建立的通话保持原控制与媒体路径，通话中禁止修改配置；网络断开不静默把通话交给另一个入口或另一台设备。
- Wi-Fi 恢复时复用已有发现与认证恢复机制。地址保存不等于在线，重连仍检查身份；DNS / DDNS 更新通过新连接时的系统解析生效，不缓存固定公网 IP。
- Watch 媒体参数新增可选 `pcm_tls`。新 Watch 客户端用 TLS 连接域名；无标记的旧私网参数继续按原样工作。旧 Watch 客户端拒绝域名参数，需要随 iPhone 更新，不会将其作为明文域名连接。Watch 必须自身能访问该公网入口，不能由 iPhone 配对成功推断 Watch 音频可用。
- 此功能不新增 APNs / PushKit 推送，不绕过 iOS 挂起限制。后台来电唤醒和短信通知仍按现有云端/蓝牙机制工作；不能把前台直连可用视为锁屏持续收听来电。

## 验证

2026-11-01：当前 VoBLE 工作树在 iOS 26.5 模拟器完成 iPhone / Watch 构建，195 项定向 XCTest 全部通过；其中 13 项覆盖域名路由与公网首次配对，其余覆盖原有配对、Tailscale 恢复、纯本地及 Relay 出口等。`git diff --check` 通过。这些结果不代表公网网关或真机音频验收。

自动化回归覆盖旧路由解码、TLS 地址与端口边界、局域网/远程记录共存及删除、同设备有限次回退、控制身份验证、TLS 失败不保存、修改时保持设备绑定、通话保护、迟到验证取消，以及 iPhone / Watch 的 TLS 媒体参数。

构建与 XCTest 按 `iOS/README.md` 执行。发布前还需用实际 NAS、软路由、安卓、iPhone 和 Watch 验证：首次私网配对及首次 HTTPS 域名配对；公网 IPv4/IPv6；证书过期/不匹配；双向音频与短信；回到局域网；DDNS 地址更新；安卓重启端口变化；网关断开；通话中切网；关闭配置和删除设备后的重启；后台与锁屏行为。模拟器与协议测试不能代替这些实机结果。

TLS 客户端保留系统信任评估，参见 [Apple Network.framework TLS 配置说明](https://developer.apple.com/documentation/network/creating-an-identity-for-local-network-tls)。

本实现基于 [PR #11](https://github.com/kai-wu-cortex/AirSIM/pull/11) 的 TLS 直连方案，适配当前 VoBLE 分支的取消、并发探测与纯本地机制，并增加 HTTPS 首次配对。尚未部署、安装或完成真实 NAS/公网通话验收。
