# Issue #26：采集音量与安卓本机声音策略

日期：2026-11-05。工作分支：develop。

[原反馈](https://github.com/kai-wu-cortex/AirSIM/issues/26)：Pixel 6 的通话音量调高后，iPhone 听到的声音随之变大，随后被自动压低。源码确认旧策略将通话音量维持在最低非零档，看门狗把用户调高视为偏离目标；Pixel 6 的采集/音量耦合仍需真机电平验证。

## 用户入口

安卓 AirSIM → 设置 → **远端通话音量与本机声音**。

| 选择 | 行为 |
| --- | --- |
| 自动适配 | Google Pixel 6 保留通话音量；其他设备沿用最低非零音量策略。只针对已有具体反馈，不据厂商或芯片推断所有型号。 |
| 保留通话音量 · 优先远端声音 | 不修改安卓通话音量或输出静音状态。用户在安卓通话中调整到合适档位，看门狗不强制压低；挂断后保留调整。所有机型可选。 |
| 降低本机声音 · 最低非零音量 | 维持最低非零通话音量，挂断时恢复原状态。适合已验证不影响远端响度的设备；不能保证完全静音。 |

设置保存在本机，独立于 VoWLAN/VoBLE/使用同一 PCM 桥的云端传输方式。若此前音量已经很低，保留模式不会凭空选择“最佳音量”，需要手动调高。

当前未实现独立于采集链路的硬件输出衰减。因此保留模式明确提示：安卓本机可能发声或漏音。没有伪装成已支持独立静音，也没有通过 iPhone 软件增益掩盖低质量采集。

## 实现

- 输出策略从传输类型中分离，设置由 App 解析后传入权限服务。
- 保留模式的 watchdog 快照认可用户当前音量，不因变化执行压低/取消静音；原有服务探测、权限通道恢复仍保留。
- 通话中从降低模式改为保留：先恢复压低前的音量。恢复失败保留旧快照并报告失败，供后续重试；不会保存已压低的档位作为新基准。
- 仅切换 VoWLAN/VoBLE 不重新保存音量快照，避免最终只恢复到最低档。
- Shizuku Binder 增加内部 transaction 8；Root 通道增加对应 `output_policy` 请求。旧 transaction 3 保留。新策略遇到不支持的旧权限服务会明确失败，不静默使用旧降音量逻辑；需重新启动权限服务或安装后续增加版本号的包。
- 服务诊断 revision 更新为 12，快照含 `output_policy=preserve_volume` / `minimum_nonzero_volume`；诊断说明同步更新。
- 没有修改 Relay、iOS、U30Air Agent 或 AVF 网络 API。此前 Issue #20 未提交修复保留。

## Pixel 6 真机验收

1. 确认设置为自动适配，页面显示当前保留音量；权限服务正常应用策略。
2. 手动拨打测试电话，在 Pixel 6 调高通话音量；保持至少一分钟，确认不再自动回到最低档，iPhone 声音保持清晰。
3. 分别测试 iPhone 听筒、扬声器和耳机；确认没有用切换输出掩盖采集音量问题。
4. 挂断后检查 Pixel 6 音量仍是用户调整值，再次拨号不回到最低。
5. 通话中先选择降低、再改保留，确认恢复压低前音量；验证实际本机漏音程度是否可接受。
6. 导出安卓音频诊断，核对 `output_policy`、音量和 watchdog 修复事件。真实 PCM 响度与声学漏音尚未验收。
