# iPhone 200：连接、推送、解密异常与小组件反馈

基线：iPhone 199、已实测恢复彩铃和静音的 Android 139。Android、Relay 及通话媒体协议不变。

## 变更

1. 本地连接显示重新发现、验证、Wi-Fi 路径不可用、验证失败及原因；记录当前运行期间的最近失败/成功时间。移除不适用于专用 VoWLAN 版本的“已回退云端”提示，不凭不可达猜测安卓休眠或重启。
2. 设置 → 连接与设备 → 连接与推送诊断（帮助与诊断也可进入）：通知授权/声音/提醒权限、只读 Relay HTTPS 身份检查、按已配对 agent ID 匹配的云端心跳状态、最近检查时间、普通推送/扩展及 PushKit 接收时间。纯本地或云端通知关闭时不访问 Relay。心跳仅在线判断，服务端接口没有暴露精确心跳时间，不伪造时间。
3. App/通知扩展共同记录短信解密失败、密钥 kid 不匹配、首次解锁前密钥不可读、加密后收到明文等异常。数据保存到既有共享 Keychain 组下独立的元数据服务，带跨进程互斥锁；最多 60 条，按 agent 与 delivery 的哈希去重。不保存短信正文、号码、推送 token、密钥或密文。异常通知在可获得设备名时标明来源；短信列表显示异常入口；诊断页按设备提供重新配对入口。旧记录不会因重新配对而误标恢复，同一条短信后续确实解密成功才更新状态；支持手动清除诊断历史。
4. 小组件分别显示尝试时间、最近成功时间、正在刷新/成功/失败/中断，以及固定错误原因。请求失败不更新成功时间。跨进程非阻塞文件锁避免按钮与系统刷新重复查询；刷新启动写入进度，完成落盘，手动 intent 请求 timeline 更新。系统请求不会形成自触发刷新循环；intent 完成后的短时间 timeline 请求复用已持久化结果。保持约 15 分钟的系统刷新请求，实际调度由 iOS 决定，不保证即时绘制“正在刷新”。

## 验证

- 实际共享源码的 macOS SwiftPM 回归：41 项通过，包含加密向量/篡改、通话隔离、诊断元数据读写/损坏恢复/历史上限、刷新中断过期与脱敏错误文案。
- iOS App、通知扩展、小组件和完整测试目标 build-for-testing 成功。未声称完整 iOS 测试套件已运行。
- 深度签名验证通过，覆盖安装 iPhone 200 成功。安装包：outputs/AirSIM-iPhone200-health-diagnostics-widget-refresh.ipa。
- 通知扩展最初尝试 App Group 文件存储时遇到现有签名不含该能力；最终改用原有 E2E 共享钥匙串，不新增签名能力或更换配对密钥。

## 实机待验收

- 打开诊断页执行只读检查，核对权限、Relay 与本人安卓的心跳；新接收一条短信后核对接收时间。
- 点击小组件刷新，核对尝试与成功时间。安卓暂时断网后再点，确认原因和成功时间保留；恢复后再次刷新。
- 真实断网期间仍可能不可达。本轮改善状态反馈和记录，不能保证 iOS 后台常驻或实时小组件刷新。
