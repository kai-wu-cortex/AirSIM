# Watch／iPhone 206 预览：通话、短信与连接测试报告

日期：2026 年 11 月 9 日。状态：源码和模拟器预览，未安装到任何实机。

## 目标与范围

用户后续已取消代码隔离限制，允许增加必要的 iPhone 配套接口。当前实机仍保留 iPhone 204／安卓 140；签名 IPA（内含 Watch 204）、APK、源码及校验清单保存在 `outputs/rollback-iPhone204-Android140`，本轮复核哈希保持一致。

新版需要 Watch 与 iPhone 配套更新，安卓继续使用 140。普通 iPhone 通话核心文件 AppModel、AudioSessionController、DeviceCallActionRouter、AirSIMAPI、VoIPPushController、CallKitController、E2EKeyStore、ConnectionModePreference 与 204 基线逐字节一致。iPhone 的新增业务集中在 WatchCallCoordinator，另增加共享短信载荷和版本元数据。

## 实现内容

### 来电与接听

- Watch 自身限制 VoWLAN，旧云端许可缓存不能开启云端音频；Relay 推送保留。
- 本地音频完成认证握手后才回报媒体就绪；PCM 或彩铃先到不再等同于安卓已接通。
- 安卓确认接通、音频就绪可以任意先后到达；当前通话同时满足条件才进入 active。
- 拨号回复前先到的 active 镜像按 UUID 暂存，最多 8 条，其他通话不能覆盖本次应答。缺少匹配镜像时请求现有最新状态。
- 媒体完成、断开、排队播放同时核对通话 UUID 和连接代次。挂断清空初始声音，避免旧音频进入下一通。
- 对接听中立即挂断，使用已认领的原通话结束路径，不再只尝试拒接仍在响铃的来电。
- 旧接听失败只清理自身 UUID；迟到成功回应不再操作下一通电话。系统操作超时、CallKit 重置会清理待拨号状态和本机音频。
- 在命令安卓接听前检查 Watch 麦克风权限；未授权时保留提示，避免先接通再因无法录音结束。

### 连接速度与初始音频

- 无额外首连等待。重试等待为 150／350／700／1000 ms，后续保持上限，保留原有总预算。
- 放弃一次连接时立即使其代次失效，迟到 ACK 不会误报连接成功。
- 播放引擎启动前先到的音频最多保留 160 ms，启动后立即交给播放器；不额外等待凑满，不延迟上行发送，挂断清空。它不能代替网络质量修复。
- 诊断中记录 iPhone 回应、握手完成、首段下行数据的实际耗时。起点为本次拨号或接听处理，不代表按键到实际听见声音的完整端到端耗时。

### 挂断确认

- 新增只读、绑定原设备及通话 UUID／后端 ID 的结束查询。命令 ACK 或本机 ended 不视为安卓终态证据。
- 确认成功显示 5 秒后隐藏；暂未确认时自动复查，前 10 次间隔 2 秒，之后间隔 15 秒，另加请求耗时。
- 同一设备重新认证连接后优先使用其当前 API；不会改查另一台默认设备。确认记录失效时明确提示，不能猜测成功。
- 与旧 iPhone 204 配合时，仅按原协议显示“iPhone 已接收挂断请求”，不伪造安卓结束确认。

### Watch 短信查看

- 增加最近短信列表、正文、时间、方向、SIM、未读标记及多设备选择。
- 从 iPhone 已同步的本地记录读取最近最多 30 条；不强制唤醒安卓拉取全量短信。后台推送尚未落入本地记录时，列表可能暂不包含该条。
- 仅展示已保存配对记录中对应 agentID 的短信，排除其他设备及无来源的旧记录。消息 ID 使用摘要，不把含正文的旧指纹直接传到手表。
- 单次载荷限制 28 KB，正文过长时明确标注截断；UTF-8 字符边界及 JSON 转义后的实际大小均检查。
- 打开正文成功后单独提交已读确认；iPhone 实际写入并更新未读状态后才在手表清除未读。失败时提示“已读状态尚未确认同步”。
- 正文及列表只在 Watch 内存中使用，不向手表转交短信解密密钥；继续使用 iPhone 已有解密流程。
- RPC 设置 10 秒超时，重复或迟到回应只完成一次。设备变化或旧请求迟到不能覆盖新列表。
- 来电及通话优先，短信查看页收到来电时自动退出到接听界面；iPhone 通话处理中不执行新的收件箱整理。

### 小屏幕界面

- 修复 40mm 来电按钮及拨号盘底排裁切，主操作可直接看到。
- 挂断反馈复用号码显示区，完整详情可从信息按钮查看，避免反馈挤掉键盘。
- 模拟界面明确使用测试联系人和模拟短信；只在 DEBUG 测试参数下启用，不发起真实电话。

## 验证边界

- 未安装实机；没有驱动真实 Android Telecom 或运营商电话，没有验证真实 Watch 麦克风、扬声器、锁屏唤醒及双端声音归属。真实彩铃、双向通话、安卓静音和挂断无漏音仍需实机回归。
- 模拟器画面使用明确的 DEBUG 数据；iPhone 运行测试使用内存 HTTP 夹具。未实际完成 Watch 与 iPhone 的 WatchConnectivity 配对链路验证，不能据此承诺实际接听已“丝滑”。
- 回环测试的毫秒数只反映同一台 Mac 上的模拟网关，不能用作 Watch／Wi-Fi 性能数字。
- 后台挂起或强制退出期间，系统是否唤醒和调度仍需实机验证；自动复查只在 App 获得执行机会时运行。
- 旧 204 的额外基线运行曾因模拟器测试进程无法启动而失败，没有形成完整的基线动态对照。最终结果来自配置正确的 206 运行测试与核心源码一致性核对。
- Watch 模拟器桌面在连续安装启动中曾出现一次系统 Carousel 启动错误，恢复后完成了前后画面检查；不将该环境故障算作通过，也不据此判定实机应用崩溃。
- 原有音频会话在主线程激活／停用的系统性能提示仍可见；本轮保留已验证的 iPhone 音频核心。真实耗时通过后续设备测量判断。

## 下一步实机验收（本轮不执行安装）

1. 授予 Watch 麦克风权限后，锁屏呼入并接听，核对首段声音、双方说话及诊断耗时。
2. 接听后立刻挂断、对方先挂断、连续两通，确认无旧通话复活或声音串入。
3. 看短信列表及长正文时呼入，确认接听按钮立即可操作。
4. 新短信核对发送人、SIM、正文及 iPhone／Watch 已读同步；断连时检查错误和恢复。
5. Wi-Fi 变化、Watch 休眠及 iPhone 不同后台状态分别测试，不混用结果。
6. 保留当前 204／140 回退包，覆盖安装使用相同应用标识和签名；不先卸载以避免配对和记录丢失。
