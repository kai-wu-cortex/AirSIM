# iPhone 201 / Android 140：启动检查、挂断确认、音频自检与空号召回

基线：iPhone 200 / Android 独立测试版 139；原 AirSIM 已禁用。继续仅 VoWLAN 通话，Relay 仅推送。

## 行为

- 拨号盘号码为空时绿色呼出键仅填入最近一次呼出号码；第二次按键才调用既有 dial()。优先比较本地历史中 outgoing 的 startedAt 与已保存的最近提交时间；来电不参与召回。不会覆盖已有输入；无历史时保持禁用。召回不修改当前设备或 SIM，不自动发起电话。
- 安卓 /api/status 可选增加 readiness：默认电话角色、拨号及通话状态权限、当前缓存的 Shizuku/Root 通道状态、音频桥进程、配对存在、开机运行时间。只读采样不申请权限、不重启桥。iPhone 诊断页按已验证的具体设备读取；旧版缺少字段显示未知。进程存在并不证明端口或真实采集正常。
- 路由挂断仍先退出本机界面，再向捕获的原后端及 backend ID 发命令；之后只用准确原生/规范 call ID 查询终态。另一个活动电话、空状态、命令 ACK 不构成确认，同 ID 活动记录优先于矛盾历史；失败明确显示“iPhone 已结束，安卓尚未确认”。后续同设备、同 ID、同传输代次的认证终态可以更新确认。旧确认回调不能覆盖新一次挂断状态。不自动重拨或对当前任意电话补发挂断。
- 音频握手后以单调时钟观察真实 PCM 数据到达；6 秒无下行数据给出提示，静音数据仍算数据到达，不误称对方没有说话。帧到达且播放引擎运行只报告数据/引擎状态，不承诺声学效果。
- “恢复播放”仅启动当前本机引擎/播放器，不关闭 PCM、不重新拨号、不切设备，不改变安卓静音/麦克风隔离。网络断流不能靠本机播放恢复解决。

入口：设置 → 连接与设备 → 连接与推送诊断。通话页异常时出现恢复播放按钮，挂断确认在拨号页显示。

## 验证

- 45 项共享源码测试通过：包含准确终态确认、矛盾状态/其他通话不误确认、启动状态旧版兼容与缺失权限处理，以及原有加密/通知隔离/小组件回归。
- 空号召回 XCTest 用例已加入并随完整 iOS 测试目标编译通过；本轮未执行完整 iOS 测试套件或声学测试。
- iPhone 201 深度签名验证及覆盖安装成功。
- Android 140 构建及 pre-33 Java API 检查通过，沿用独立测试版包名、原签名及配对数据；覆盖安装后 versionCode=140。
- 进程列表确认仅测试版应用、测试版 pcm_shell 及其 PhoneAudioBridge 存在；没有重新启用原应用。

待用户确认首次空号按键只召回、下一次真实呼叫/挂断提示、彩铃及静音回归。未自动发送真实电话/短信或重启安卓。

安装包位于仓库外 outputs/AirSIM-iPhone201-readiness-hangup-audio-redial.ipa 与 outputs/AirSIM-Android140-startup-readiness-test.apk。
