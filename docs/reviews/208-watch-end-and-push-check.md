# 208：Watch 通话结束与实时推送检查

## 问题与修改

- Watch 已通过独立 VoWLAN PCM 接管通话时，iPhone 控制连接的暂停或重建不再被当作 Watch 媒体断线。iPhone 在检测开始、延时到期和状态查询返回后均重新核验归属。
- iPhone 的 VoWLAN 丢失检查先通过原设备的认证 API 查询原通话的结束证据。已结束则收敛原通话状态，不再重复挂断或弹出链路中断提醒。
- 状态查询期间若挂断、新通话或连接恢复已发生，旧检查不能结束后续通话。真正的 iPhone 通话链路丢失仍执行结束和提醒。
- 断线检查自己发起挂断时解除自己的任务引用，避免终态清理取消正在执行的挂断请求。
- 推送诊断保持每次进入拨号页实时读取。健康检查和认证心跳继续并行，不使用之前的检查结果。
- 仅复用 HTTPS 连接；诊断会话无响应缓存、无 Cookie、拒绝重定向，仍经过 Relay 出站限制。
- 只读诊断对临时网络错误和 HTTP 502/503/504 最多尝试三次，间隔 200/400 ms；认证失败、额度耗尽及无效内容不按成功处理。
- 检查取消会传递到网络请求；取消不显示为失败。失败文案区分超时、网络异常、认证失败、额度耗尽、配置和响应异常；诊断记录不保存请求密钥或响应正文。

## 验证

- 首轮 51 项：5 项跳过，0 失败。
- 第二轮 52 项：47 项通过，5 项跳过，0 失败。跳过项仅限本版本禁用的 VoBLE 专属场景。
- 覆盖 DeviceCallActionRouterTests、WatchCompanionCallRaceTests、WatchCompanionSMSProtocolTests、RelayEgressGateTests。
- 新增：安卓明确终态、查询中恢复、查询中 Watch 已结束、真实链路丢失、取消网络请求、临时错误重试、认证/额度不重试、每次重新取结果。
- 当前 Relay 的 /healthz 检查返回 HTTP 200，身份验证正常。旧版本没有记录此次拨号页诊断失败的具体原因，因此不能仅凭这次健康检查断言偶发失败根因。
- 实机仍需确认：Watch 接听后挂断再打开 iPhone，无旧断线提示；反复切换拨号页与前后台，检查状态正常收敛，真正网络故障显示对应原因。
