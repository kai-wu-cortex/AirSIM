## 修改

1. iPhone 自动模式先查已验证本地路线；若暂无路线但推送已有 authenticatedMediaURL 且云端启用，立即使用云端，不再等待整轮本地发现。已有可用本地路线仍优先；本地模式、没有云端凭据或云端禁用时保留本地恢复等待。蓝牙入口不变。
2. 本地等待正确响应任务取消。新增 answer_route_selected 日志记录模式、路线、耗时和会话身份，避免下次只能间接推断耗时。
3. 仓库中的模块 Agent 将 Relay 的精确 `{event, role}` 状态通知与通话控制区分。仅识别 peer_connected / peer_disconnected / owner_claimed 及已知角色。含动作或身份等额外字段的消息仍走原控制验证；没有放宽 call ID / UUID / generation 检查。

Relay 协议无需改变。MU300 适配仓库使用固定上游加补丁，当前设备不会因为修改此仓库而自动更新。初次 iPhone 修复时未改该独立仓库；用户接回 USB 后，已继续完成下述模块修复。没有刷写固件或部署服务器。

## USB 模块日志确认的根因与修复

设备 U30 Air，OpenWrt 25.12.6、5.4.254-gb50db5b6224c、插件 0.1.0_p20261123-r26。实际旧 Agent 未包含 R27 TEL 投影；此外 R27 的严格号码比较也不能把大陆本地手机号与 +86 视为同一身份，单独升级 R27 不足以覆盖这次现象。

- 原 incoming 记录在 20:58:40 创建，接听已确认 active。
- 20:59:00.798 同一槽位的号码由 11 位手机号变成 `tel:+86<同一号码>`；没有用户号码写入本报告。
- Agent 在同一时间结束旧 ID，并新建另一个 incoming ID；新 ID 直到 20:59:17.374 才结束。系统日志的 native termination 在 17 秒时出现，旧 ID 的结束来自本地状态替换。
- 因云端会话绑定旧 ID，watchdog 判定旧 ID 不存在并发送 remote_ended。iPhone 按协议结束了该会话。

修复位于独立适配仓库 `/Users/kyle/codex project/U30Air/out/openwrt-sms/patches/AirSIM-mu300.patch`，保持固定 AirSIM 基线 cc2ade3：

1. 保留已有 R27 TEL/SIP 安全投影，在同一活跃 CLCC 槽位比较中，允许严格匹配的大陆 11 位手机号与显式 +86 形式等价；不改拨号/SMS 目标，不按任意尾号匹配，不删除扩展/上下文等参数。
2. 原有不同号码、方向变化、active 回到 setup 的槽复用保护不变；真实确认结束仍结束原通话。
3. 同步本次 Relay 状态帧分类，消除无身份的伪控制错误。

先用日志等价的合成测试复现了旧代码失败；修复后完整隔离 Agent race 测试、vet 与 Linux ARM64 构建通过。重新应用固定基线补丁的 99 份源码/fixture 与测试版本哈希一致。

用户接回设备后，确认通话与 PCM 空闲、无原生短信发送任务，再备份并仅替换 Agent。运行版本已确认 `0.4.7-mu300.cold-answer-20261125`，包版本仍为 R26（不是完整 R27 升级）。原二进制保存在设备 `/mnt/mu300-disk/extra/airsim/backups/airsim-agent-pre-cold-answer-20261125`；配对、内核、DSP、桥和配置保持原文件。新 Agent 可达、服务恢复、音频桥空闲且无错误。尚待用户在冷启动条件下完成真实接听/双向音频验收。
