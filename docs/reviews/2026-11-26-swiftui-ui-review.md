# AirSIM SwiftUI UI Review

使用本机 Xcode 27.2 导出的 Apple `swiftui-specialist` 检查视图结构、状态依赖、列表标识和交互。以下为源码评审，真机帧耗时和辅助功能表现需要单独验证。

- [x] 全局导航、五个标签页和会话过渡
- [x] 拨号、通话和设置在不同窗口尺寸下的布局策略
- [x] 灵动岛、桌面小组件和 Watch 的列表、焦点与刷新行为

## 本次修复

短信列表原本为同一个列表注册了两个导航栏搜索配置。去掉重复配置后，搜索回归通过，录像仍显示原生大标题会在返回时展开，首行前后相差 52 点。现在大标题和原生搜索框由列表内容布局，导航栏负责工具按钮和系统返回手势。会话完全进入后再确认已读，相同时间的会话按发送者标识稳定排序。会话头像和号码尺寸保持现有设计。

## 待办

| 优先级 | 区域 | 发现与建议 |
| --- | --- | --- |
| P2 | 最近通话、短信、联系人 | 最近通话在 `RecentsView.groups` 里反复分组。短信列表从 `AppModel` 读取全部消息，并在分组搜索时调用 `ContactStore.contact(for:)`，查号码最多遍历通讯录两遍。两处都能被无关的连接状态更新触发。建议先用包含多年记录和大型通讯录的数据测量，再按通话记录、短信、联系人索引拆出窄依赖。 |
| P2 | 最近通话、短信 | `PhoneListMetrics.timeColumnWidth` 固定为 76 点。辅助功能大字号和较长的本地化日期可能被单行截断。建议常规布局保留现有对齐，大字号改为时间换行布局，并验证长号码和未读角标。 |
| P2 | 短信输入栏 | 录屏中，推入时输入栏还会随着标签栏隐藏调整一次底部位置。建议单独核对输入栏与键盘的安全区，验证输入栏从首帧开始就位。 |
| P2 | 灵动岛和锁屏实时活动 | 设备行使用数组位置作为 ID。切换当前设备或分页时，同一位置可能代表另一台设备，影响 SwiftUI 跟踪行身份及焦点。设备已经有 `agent.id`，建议用设备 ID 标识行。小组件短信预览的索引标识另有不导出旧短信正文 ID 的约束，若迁移应使用不含正文的稳定 ID。 |
| P2 | Watch 短信 | `WatchSMSConversationView` 每次末条记录 ID 变化都会滚到底。用户读旧消息时也会被带离当前位置。建议保留首次定位，只有原本接近底部时才跟随新消息。 |

拨号页和通话页都根据窗口尺寸及辅助功能字体选择布局，并允许滚动。设置首页已用值快照隔离无关刷新。这几处在本轮源码检查中没有发现与短信跳动相同的重复搜索或行身份问题。

## 验证

- Xcode 27.2 签名构建通过，iPhone Air 已覆盖安装并启动 0.9.8（196）。
- iOS 27.0 模拟器的短信导航用例通过，包含单搜索框、首行前后位置差不超过 2 点、已读更新、短拖取消、长拖返回、键盘打开时返回和底部标签栏恢复。录屏检查了列表推出和滑动返回。
- 搜索用例在模拟器启动同步时超时。超时后日志仍验证了联系人与正文搜索，以及清除输入框；完整搜索用例记为超时。
