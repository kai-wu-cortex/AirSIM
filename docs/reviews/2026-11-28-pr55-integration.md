## 三项评审问题的处理

1. **退出恢复（P1）**：权限服务恢复失败时保留音频执行器、原始状态和桥控制权，退出进程须等待恢复确认；不再一次恢复失败就关闭执行器。恢复采用单个任务、每次系统调用最多等待 250 ms，重试间隔逐步退避到 10 秒。迟到的系统写入完成后仍可再次恢复。
   - 实验隔离增加 20 秒所有者租约，仅客户端持有隔离意图时续租。状态查询本身不续租，过期或正在恢复的会话不能被迟到的心跳复活。
   - 修改系统音频前保存原麦克风状态、流静音状态及独立输出索引。保存失败不进行静音；正常恢复后删除记录。同次开机重启权限服务时读取记录，先取得排他桥控制权再恢复，避免 Root／Shizuku 竞争时干扰另一服务的活动通话。新开机不重放旧状态。
2. **默认策略（P2）**：取消 realme RMX3888 自动启用，所有型号保持原「自动」策略。只有手动选择 `isolate` 才进入实验路径，界面标明默认关闭与机型验证范围，并拒绝通话中开启。可切回保留音量／最低非零音量。
3. **测试入口权限（P3）**：`test.sh` 保持 `100755`，可直接执行；保留 PR 的可移植 `mktemp` 修复。

## 对现有通话的约束

- 默认模式不调用新增租约 IPC，不创建恢复记录，不静音本机麦克风；Pixel 6 的保留音量与其他机型的最低非零策略保持不变。
- 实验模式仍复用已有远端身份、唯一通话和 PCM 就绪判断。VoWLAN、VoBLE、云端均在接通后才隔离，不在响铃／拨号时启用，也不延续到原输出尾音等待窗口。
- 媒体丢失、挂断、出现第二通电话或服务销毁时请求恢复；不由隔离逻辑挂断通话，不重新启动系统音频服务。
- 已有短信、云端早期媒体、媒体所有权与默认音量策略的回归一并运行。

## 自动化验证

- 直接执行 `./android/phone-control-app/test.sh`：退出码 0，63 组通过输出。
- 真实 `AirSIMInCallService` 生命周期夹具：31 个场景，包括三种传输的未接通／接通／媒体丢失／挂断及第二通电话、服务销毁、迟到刷新；保留全部既有场景。
- 恢复记录及租约：22 项检查，覆盖同次开机恢复、原麦克风已静音、重启系统后的记录失效、损坏或链接文件拒绝、写入失败不改变音频，以及各机型默认关闭。
- 真实权限服务＋有界执行器夹具：17 项检查，覆盖退出恢复失败后重试、退避、超时写入迟到、App 失联、权限服务重启和默认模式无租约 IPC。
- PCM 排他控制权：11 项断言，包括竞争服务不能提前读取／恢复正在使用的隔离状态；服务策略测试另验证非所有者不能隔离。
- 完整 APK 构建、Java API 兼容扫描、APK Shizuku 集成检查及差异空白检查作为合入前检查。

测试中的音频、电话和 Binder 系统边界使用夹具；未拨打电话、发送短信或录音。这些结果证明控制逻辑与回归通过，不代表所有厂商声学效果通过。

## 验收边界

- 本轮没有安装或发布 APK，没有替用户开启实验选项。跨机型的真实接通、双向语音、耳机切换、挂断与失联恢复仍需验收。
- 系统 Binder 永久阻塞时无法强制取消已提交的音频写入；会保留恢复证据，不谎报已恢复。整个权限进程被强杀时，要等新权限服务恢复才可继续清理。
- 恢复记录位于 `/data/local/tmp`，使用仅所有者可读写的临时文件原子替换，不含号码或通话内容。Shell 无权读取上次 Root 创建的记录时拒绝接管，需原权限通道恢复或系统重启，不放宽文件权限绕过保护。
- 现有手机上加载的权限服务可能仍是旧代码；实际试用前需要更新 APK 并重新加载权限服务。默认通话不会调用新增实验事务。
