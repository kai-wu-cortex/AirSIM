# 锁屏云端接听与前台状态接管

## 已观察的证据

读取当前 iPhone 的本地诊断，不录音、不代拨号。2026-11-25 18:59 的记录显示 CallKit 音频已激活，云端 answer 已被 Relay 转交，iPhone 音频引擎也启动了；没有观察到 Agent 的 active 确认或下行 PCM。Relay 的 delivered 仅表示转交，不能证明基带已经接听。

## 已修复的代码缺口

- 云端 answer 开始时发布 connecting 生命周期，而不是只更新 session 私有字段。系统已经接受的来电不再继续显示第二次接听按钮。
- 冷启动接管、返回前台和重复接听入口按同一 call ID / UUID / generation 恢复云端状态，直到 Agent 确认才显示 active。
- 选择云端路线后，在网络等待之前锁定路线；释放同一系统 UUID 的未接听局域网展示绑定，不发送挂断、不抢夺已拥有媒体的本地通话。迟到的发现不能重新绑定到来电页面。
- 冷启动处理器兼容 CallKit 激活先到及媒体连接先到两种顺序，已接受的 connecting 来电也可以启动音频。
- 未收到 active 回执的已接受来电也纳入现有媒体恢复预算，最多 3 次重建；未接通的呼出早期媒体不因此被强制恢复。引擎运行但无 PCM 不再直接标成音频已连接。

## 验证与限制

最终代码的 8 项定向模拟器测试通过（`/tmp/airsim-cloud-handoff-retry-tests.log`），覆盖接管身份、连接中/已接通区分、迟到局域网事件、旧代次/UUID、结束后不可复活，以及两种音频启动顺序与恢复上限。本次没有更改 Android、模块 Agent、Relay 协议，也没有线上部署。

代码层修复不能证明实际 Agent 无声已经完全消除。仍需使用自动模式锁屏接听、返回 App 的相同流程复测，并同时检查模块 active 回执和下行音频。不得把 delivered 或 iPhone 引擎启动当作双向通话验证。

补充：扩展路由套件中一个旧测试把能力查询误判成实际接听，已修正其 mock 并在最终定向轮验证通过。全套扩展运行另遇系统 CallKit 测试挂起，未宣称全套通过；最终采用隔离系统回调的测试完成本次变更验证。Xcode 测试注入曾阻塞，重新启动测试会话后上述 8 项全部通过。
