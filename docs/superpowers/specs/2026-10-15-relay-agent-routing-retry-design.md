# Relay 重复连接与多 Agent 定向优化

日期：2026-10-15。状态：用户于 2026-10-16 回复“执行”，已确认书面设计；实施计划待审阅，尚未修改产品代码、部署或发布。

## 目标与范围

用户要求优化已定位的 Relay 重复请求问题。结果应是：一个 iPhone 配对多个安卓时连接互不挤占；拨号、短信和通话控制只交给目标安卓；短连接失败不会不断清零退避；重复投递不增加实际拨号或短信次数。

保持 VoWLAN、VoBLE 与当前连接模式独立；不改变默认 SIM、媒体编解码、正常心跳间隔，不新增 iOS Relay 状态查询定时器。本轮不处理尚未取得错误日志的夜间全部 HTTP 500，也不把它们都归因于重复连接。

不执行生产部署、真机安装、提交推送、Release、TestFlight 或账户套餐调整。现有未提交的 build 82–85 改动保留。

## 已确认依据

- `connectDeviceCommands()` 仅按 Apple `device_id` 取得 COMMANDS 对象。
- `DeviceCommandSession` 把所有安卓连接标记为 `agent`，新连接关闭该对象内所有旧 `agent` 连接。生产源代码的对应行为已读取确认。
- 本地模拟两个安卓交替连接 6 次，出现 5 次 4001 替换关闭。此模拟不发送真实电话、短信或生产命令。
- Standalone 每次握手成功立即令 `failures = 0`；之后若马上断开，普通重试回到约一秒。WebSocket 读循环丢弃关闭码及原因。
- 断线期间原有 HTTP 命令补拉每 15 秒触发，会放大频繁断连的请求数。
- Standalone Gateway 和旧 AVF 执行器已有按 command ID 串行去重；须保留，不能把重复网络投递直接等同于重复发送短信。

现网统计支持反复建连，但缺少关闭码日志，不能证明每一次断开都由互相替换造成。

## 方案选择

1. 只加大重试等待：改动小，但不能解决连接互踢及命令发错安卓，不作为最终方案。
2. 每个安卓新建一个 COMMANDS 对象：隔离直接，但会增加旧队列、结果查询、通话引用的迁移复杂度。
3. **推荐：保留每个 Apple device 的 COMMANDS 对象，在对象内按安卓 Agent ID 隔离连接和命令归属。** 不新增 namespace 或迁移已有存储结构；新增字段采用显式版本能力和安全兼容规则。

## 身份与定向契约

`device_id` 继续是 Apple 客户端的 Relay 鉴权域，`agent_id` 是该域内的安卓 Agent 实例。不能用号码或最新心跳代替安卓身份；换卡不改变 Agent ID。

- 新 Android/AVF 命令连接在现有 HTTPS/WSS 认证之外携带 `agent_id`。字段为有界、不含控制字符的非空标识，做一致的编码和验证；不是新的鉴权凭据，不能替代设备 Secret。
- 新命令连接可与其他 Agent ID 并存；只替换同一 Agent ID 的旧连接。连接 attachment 保留 Agent ID 和连接代次，关闭／错误回调不得清除另一条新连接。
- 旧请求没有 Agent ID 时进入隔离的 legacy 身份。不能从最后一次注册记录猜测它属于哪台安卓，也不能顶掉新式具名连接。
- 拨号和短信请求携带 `target_agent_id`。iOS 在用户选中设备或自动选择出唯一可用设备后快照该 ID；等待结果或切换设置不改变已提交命令的目标。
- COMMANDS 记录持久化目标。WebSocket 推送、HTTP pull、重新连接补发、alarm 重发、完成回执都核对目标；不得将发给 A 的命令交给 B，也不能让 B 完成 A 的命令。
- 相同 command ID、不同目标或意图返回冲突，不能靠重试改变原命令目标。重复完成保持现有幂等语义。
- 通话建立后把 Agent ID 固定到 call 记录。接听、拒接、挂断、救援挂断及 DTMF 跟随该通电话的 Agent ID，而不是此刻设置页选中的设备。保留 call UUID、generation、owner 和 device 所有权检查。
- 安卓上报的新来电及其后续生命周期携带源 Agent ID。Watch 的通话动作由已有 call 记录确定目标；Watch 不自行猜测最新在线安卓。

### 旧版本兼容与安全失败

- Relay 宣告支持定向协议的能力；新客户端遇到旧 Relay，不能静默忽略目标字段后继续多设备拨号。显示需升级／不支持的明确错误。
- 实施采用新的版本化动作入口来保证上述安全失败：旧 Relay 对新入口返回 404／405 等不支持错误，而不是接受新字段后忽略它。能力缓存仅用于显示，不是允许动作的安全依据；不改变媒体 WebSocket 的路径或编解码。
- 旧 iOS 缺少目标时，仅在唯一、无歧义的可用 Agent 场景解析一次并持久化目标；多个候选返回 `409 target_agent_required`，不广播或按心跳时间随机选择。
- 旧安卓缺少 Agent ID，只支持 legacy 单 Agent 部署。多个旧安卓共用身份不承诺支持，升级相关 APK／AVF Agent 后才能安全多设备使用。
- legacy 活跃连接不能被另一条无法区分来源的 legacy 新连接反复顶掉；明确拒绝并提供重试冷却。旧 HTTP pull 在无法安全确认命令归属时拒绝，不混入具名队列。
- 升级前已存在、没有目标的队列记录只按 legacy 语义处理或到期，不重新分配给新式 Agent。已有无目标通话不补猜目标；上线时避免在途通话，保留回退说明。
- 不要求清空配对数据，不改变存储 namespace，不暴露 Linux 8575/8576 或 Shell 7580。

## 重连与请求控制

### Android Standalone

- 分离“握手成功”与“连接稳定”：连续保持至少 60 秒后才重置失败计数；短连接成功后断开仍累计失败。
- 普通失败采用 3、6、12、24、48、60 秒的有界退避，再附加最多 25% 随机抖动。用可注入时钟及随机源测试，不依赖真实等待。
- 429／5xx 保留现有更慢的 15 秒起、最高 300 秒退避；遵守有效 Retry-After，不能被普通退避或抖动缩短。
- 4001 替换关闭保留独立原因，至少冷却 60 秒；重复替换继续退避。停止服务、关闭云端或变更配对立即取消旧连接任务，不让旧任务继续重连。
- HTTP pull 继续作为失联兜底，只有命令 WebSocket 不可用才运行；共享限流／故障冷却，避免 WSS 与 HTTP 两条循环在同一 429／5xx 下各自猛试。正常丢包仍有有界恢复机会。
- 握手、认证、短断、替换、限流分开记录；保留 TLS 主机名检查。解析关闭帧时检查长度和 UTF-8／有效关闭码；读写异常不得遗留 socket。

### AVF 与 iOS

- AVF 保留已有“连接稳定一分钟后清零”行为，补齐 Agent 定向字段与关闭原因；按兼容规则处理能力不足，不回退到不安全广播。
- iOS 保持当前进入前台、拨号前及显示通话实时活动前的按需状态检查。不添加定时状态轮询，不以健康探针制造额外重连。
- 命令结果查询仅在有在途命令时运行，使用取消检查和有界退避，遇到终态立即停止；失败不生成新的 command ID 重发实际动作。

## 诊断与隐私

在既有可导出 VERBOSE 日志中记录：脱敏 Agent 关联标记、连接代次、连接存活时长、关闭码、原因分类、失败计数、下一次等待、HTTP 兜底是否启用，以及命令重复投递／缓存命中。错误原因采用允许列表分类，不原样记录服务器正文。

不记录设备 Secret、完整设备 ID、号码、短信、Push token、媒体密钥、URL 查询凭据或 PCM；不新增云端日志写入定时器。Cloudflare 历史日志权限不足的事实继续注明，不为排障静默扩大账户授权。

## 测试与验收门槛

先写回归并观察失败，再实现最小修复，最后运行各组件完整测试：

1. A、B 同时在线互不关闭；同一 A 新连接替换旧 A，不影响 B；旧 A 关闭回调不能影响新 A。
2. A 的拨号／短信只发给 A；B 的 WebSocket、HTTP pull、alarm 和完成回执不能领取或完成它。重新连接仍只补发原目标。
3. 同一 ID 不同目标冲突；相同目标重放只执行一次；通话结束后迟到消息不恢复 UI、不误挂断下一通。
4. 切换选中设备后，旧通话的挂断、DTMF、Watch 动作仍发给原设备；来电源 Agent 不丢失。
5. 单 legacy 可用，多候选无目标明确失败；旧队列不串给新 Agent；旧 Relay 不伪装支持定向。
6. 连续短连接的等待逐步增加，稳定 60 秒才重置；4001、429、5xx 和停止服务有各自预期；HTTP/WSS 不绕过共享冷却。
7. Android 10–13 兼容测试，iOS／Watch 构建与回归，AVF Go 测试，Relay 单元及本地多连接集成测试通过。所有仿真号码和消息只在隔离测试中使用。

生产部署另行授权后，再比较同等在线设备数与通话负载下的连接成功次数、短断比例、HTTP 补拉量和 5xx；不能只看总请求下降就宣称修复成功。双安卓、iPhone／Watch 真机未验收前不关闭相关问题。

## 实施与回退边界

书面设计确认后再形成实施计划，默认在当前任务逐步执行，不创建额外线程或自动委派实现。先做协议与隔离回归，再改两类 Agent 和 Apple 目标传递，最后验证混合版本。

未来经授权上线顺序为：先发布安全兼容的 Relay，再升级相关安卓／AVF，最后升级 Apple 客户端。新客户端检测旧 Relay 并安全失败。生产回退不得让已定向命令变成广播；回退期间暂停新建多 Agent 云端动作，保留本地通路。上线、设备安装和发布都不是本设计文档的自动后续动作。
