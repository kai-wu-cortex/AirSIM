# AirSIM 纯本地模式设计

日期：2026-10-29（Asia/Shanghai）

状态：用户已确认聊天中的核心行为与入口交互；本文件是待确认的完整设计，不是实现、发布或真机验收回执。

代码基线：`VoBLE` / `4a941b7`（包含 PR #12、#13），结合当前隔离构建副本保留的隧道恢复、配对状态提示及手动反馈候选改动。不得覆盖原工作目录的未提交代码。此前 Worker 部署与设备安装仍处于暂停状态。

## 1. 已确认的目标

- 恢复用户理解的“之前本地模式”，复用现有 `localDual`，不建立新的媒体传输栈。
- iOS 设置页最顶部提供“滑动开启纯本地模式”；退出使用按钮与确认弹窗。
- 本地双通道：同一 Android 优先 VoWLAN，建立通话前可以选择 VoBLE；通话建立后锁定链路。
- Tailscale 使用 Android 的 VPN 地址直连，不访问、探测或验证 AirSIM Relay；仍验证配对设备身份、请求签名、防重放及控制/PCM 端口。
- 两端停止 Relay 注册、心跳、命令、媒体、推送同步及反馈上传。本地失败不得自动回退云端。
- 保留本地配对、电话、短信、CallKit、本地日志导出以及 DHCP 换址后的认证重连。
- 重启保持设置；两端确认后才显示已生效。退出后恢复此前配置，不清除配对记录。
- 常驻提示：“关闭云端推送后，锁屏来电提醒可能受限。”提供 VoiceOver 等效操作。

## 2. 目标边界与非目标

“零 Relay 请求”指受控 AirSIM 客户端与 Agent 在策略生效后，不再发起任何到配置 Relay、内置备用 Relay 或重定向 Relay 的 HTTP/WebSocket 请求。不是简单清空 URL，也不是仅关闭音频中继。适用于本地直连、自动重连、前后台切换、启动恢复、手动操作及错误重试。

已经发送的网络字节不能撤回；切换期间必须取消在途任务、断开连接并使旧回调失效。“已生效”以本机排空完成及 Android/必要 Agent 确认为界，不能把点击滑块瞬间描述为两端断网完成。

该功能不是设备防火墙，不承诺操作系统、其他 App、运营商电话/SMS、Apple 服务及 VPN 软件不联网。Tailscale 自身可能通过控制平面或 DERP；它不属于 AirSIM Relay，不能因此宣称完全无第三方服务器。严格无互联网场景使用本地 Wi-Fi、热点或蓝牙。

不改 Relay 后端协议或部署 Worker，不修改 Tailscale/ACL，不实现 RCS，不新增假音频保活，不承诺 App 被强退后始终能接听。不自动发布、安装、上传 TestFlight 或推送代码。

设计者选择：GitHub 更新检查属于独立功能，不因“零 AirSIM Relay”自动改写其偏好；本次不扩展成所有外网零请求。界面不能使用“完全断网”等超出范围的文案。

## 3. 现有结构与落点

### iOS

- `ConnectionModePreference.swift`：已有 `vowlan`、`bluetooth`、`cloud`、`automatic`、`localDual`；`CloudSignalingPreference` 与媒体模式独立。因此仅选择 `localDual` 不能作为全应用零 Relay 的证明。
- `AirSIMSetupView.swift`：设置页 `Form` 最前放入口，现有运行模式区域随后；纯本地期间云端通知和云端/自动模式控制禁用并解释原因。
- `AppModel.swift`：集中协调进入/退出，保存一次进入前快照，复用已有本地双通道启动与通话链路锁。
- `VoIPPushController.swift`、`BackgroundStandbyController.swift` 及所有 Relay 请求入口：统一读取最高优先级联网策略；覆盖注册、token 更新、命令、状态查询、诊断、自检、媒体、通知转发、Watch/Live Activity 云端同步和反馈上传。
- `VoWLANController.swift` 及本地设备目录：复用已配对身份与候选端点验证，不能把 Relay 在线状态作为直连前提。

### Android / Agent

- `StandaloneAgentStore.java` 已理解 `local_mode`、`cloud_enabled`，但需要独立、持久化的最高优先级纯本地策略，不能被旧注册包、旧 App 或开机默认值覆盖。
- `StandaloneAgentService.java`、`StandaloneCloudMediaManager.java` 及 Relay 客户端：进入时停止注册/心跳/事件上传/命令拉取/媒体连接，取消重试与在途任务；本地 VoWLAN、VoBLE、Telecom、短信服务继续运行。
- `PairingServer.java`、`StandaloneAgentGateway.java`、VoWLAN/VoBLE 已认证控制通道：承载模式协商与查询。首次本地配对无需云端凭据或 APNs token。
- `FeedbackUploader.java`：纯本地期间在读取/准备上传前拒绝，界面保留导出，不通过隐藏手动入口绕过策略。
- AVF Go Agent（`module/module-agent`，现有 `push.go` 等）必须纳入完整性判断。若 Android 正在使用 AVF，只有 AVF 也确认关闭其云端任务，才能显示两端已生效；不能只停止 Android 而让虚拟 Linux 继续上传。

具体类型名、控制路由和文件拆分留给实施计划，避免在设计阶段假装已存在 API。应优先复用已认证控制协议，而不是新增未认证管理端口。

## 4. 操作与状态

| 状态 | 用户看到的内容 | 必须满足的条件 |
| --- | --- | --- |
| 未开启 | 滑动开启纯本地；仅使用 VoWLAN／蓝牙，不连接 AirSIM Relay | 原模式保持 |
| 本机切换中 | 正在停止云端连接 | 先持久化禁用策略，取消旧任务；禁止新 Relay 请求 |
| 等待 Android | 本机已开启 · 等待 Android 同步 | 本机已排空；Android 未确认或不可达 |
| 不兼容 | 本机已开启 · Android/Agent 需升级 | 旧端不支持确认协议，不能谎报全链路生效 |
| 已生效 | 纯本地已开启 · 已同步当前绑定 Android | 当前 peer、策略版本及必要 Agent 确认均有效 |
| 退出中 | 正在恢复此前设置／等待 Android 同步 | 经用户确认，尚未完成恢复 |

滑动完成才触发状态变更，中断拖动不生效；连续触发幂等。VoiceOver 提供与滑动相同的明确操作，不要求完成拖动手势。入口位置与交互已由用户明确指定，不再重做整页布局。

设计者选择：有活动电话时禁止进入/退出并提示“请先结束当前通话”，不擅自挂断或中途更换媒体链路。

### 进入

1. 确认无活动通话，保存首次进入前连接模式、云端通知偏好及受影响端的云端配置快照；重复滑动/重启不得覆盖原快照。
2. 原子持久化本机禁用策略和操作标识，再停相关任务与推送订阅，废弃旧网络任务代际，切换到 `localDual`。
3. 通过当前已配对设备的认证 VoWLAN 或 VoBLE 通道发起幂等切换。IP 可变，目标身份不得变。
4. Android 先持久化，再停止云端任务；若有 AVF，向 AVF 同步并等待真实确认。返回生效策略、版本、设备身份和排空结果。只有完整确认才进入已生效。
5. 失败、超时、重启均保留本机禁用状态；通过本地通道重试，不借 Relay 找设备。

### 退出

用户点击“退出纯本地模式”，弹窗说明将恢复之前云端设置。取消不改变任何状态。

设计者选择：确认后首先通过本地通道恢复受影响 Android/Agent 的进入前配置，确认后再恢复 iPhone 快照并解除策略。若对端不可达，显示退出待同步，本机仍禁止 Relay；不能把待同步状态显示为已恢复。退出期间若崩溃，下次启动继续同一幂等事务。

在纯本地期间产生的历史通话/短信/通知事件，不自动补传到 Relay。退出后恢复的是配置与新的云端订阅；历史短信仍可在本地按既有去重机制同步，不能把过期来电重新变成 PushKit 来电。未成功发送的短信命令不得因模式切换自动重放。

## 5. 同步、旧客户端与多设备

设计者选择：iOS 开关是本机全局联网策略；Android 的禁止云端策略是该 Android 整机级的。卡片确认只针对当前绑定 Android，不声称控制所有历史配对设备。切换绑定设备后必须重新读取状态并同步，未确认前不能沿用前一台的“已生效”。其他未绑定 Android 不做后台远程修改。

Android 记录策略修订号及发起配对身份，重试携带操作标识；晚到回复不能覆盖较新状态。模式查询与变更都使用现有配对鉴权和防重放，不依赖 Relay token。

Android 显示该模式影响整机云端功能；其他已配对 iPhone 的普通注册/云端开关不得解除限制。设计者选择：原发起者可按退出事务恢复；Android 本机明确确认退出也可解除。若发起者配对已被删除，须在 Android 本机确认，不能依靠其他客户端越权解除。并发冲突返回当前策略修订号，重新读取，不自动争抢设置。

设计者选择（独立审阅后补齐）：进入前快照按 Android 身份与策略事务分别保存。若在 A 上开启后换绑 B，明确告知 A 仍保持纯本地；对 B 重新协商，不能把 A 的快照用于 B。退出只恢复当前绑定且由该事务控制的设备，不后台修改未绑定的 A；A 可以在 Android 本机退出，或重新绑定后经用户明确操作恢复。删除配对不等于远程退出，未恢复设备的提示不能因换绑就丢失。

设计者选择（独立审阅后补齐）：Android 本机明确操作优先于 iPhone 的自动重试。iPhone 收到较新修订号的本机退出状态后，取消旧切换事务重试，保持自身禁止 Relay，显示“本机纯本地 · Android 已退出”。不得继续显示两端已生效，也不得自动重新切换 Android；需要用户点击“重新同步”明确开启新事务，或主动退出 iPhone 纯本地。连接断开无法获取最新状态时标注“对端状态待确认”，不能永久沿用旧 ACK 当作当前确认。

仅支持旧 `local_mode` 字段但没有新能力/状态确认的设备，不能算完整支持。允许本机先停止 Relay，并明确要求更新对应 Android/AVF；不为兼容而撤掉安全验证。

全新未配对 iPhone 可以先开启：显示“本机已开启 · 等待本地配对”。Android 上由用户开启本地配对入口；新配对请求携带策略意图，并在对端确认纯本地策略之后才展示全链路完成。

## 6. 网络与后台边界

- 请求的创建、发送、重试、重定向和响应应用均需检查策略/代际，避免只在 UI 层阻断。系统恢复任务、偏好读取、旧缓存、云端自检按钮不能旁路。
- 停止现有 WebSocket/HTTP 及定时任务；保留必要本地前台服务。不删除配对密钥，不借用其他 Android 的路由。
- 通过设备身份验证处理 DHCP、热点、VPN 地址变化；控制与 PCM 必须分别有效。本地探测失败就是离线，不能用 Relay 可达性修饰状态。
- 不为“注销旧云端记录”在进入后额外发送 Relay 请求。旧记录可能暂留服务端，迟到 APNs 也可能出现；零请求不等于删除历史服务器数据。
- 迟到 PushKit/通知回调必须遵守平台要求并完成回调，必要的 CallKit 处理复用现有合法逻辑；不得由它恢复云端注册、抓取 Relay 状态、启动云端媒体或自动执行旧命令。不得简单丢弃 VoIP 回调导致系统处罚。此过渡必须单独验收。
- 本地 CallKit UI 可以保留，但无云端 PushKit 就不承诺与云端相同的后台唤醒。蓝牙状态恢复受系统条件限制。Wi-Fi 与 VPN 直连本身不是后台唤醒机制。

参考：

- [Apple：Responding to VoIP Notifications from PushKit](https://developer.apple.com/documentation/pushkit/responding-to-voip-notifications-from-pushkit)
- [Apple：Bluetooth State Restoration app relaunch rules](https://developer.apple.com/documentation/technotes/tn3115-bluetooth-state-restoration-app-relaunch-rules)

## 7. 验收与实施顺序

### 自动化

1. 状态机：进入、重复触发、取消拖动、退出取消、快照恢复、进程重启、离线对端、旧端、不匹配身份、超时与乱序 ACK。
2. 出口拦截：每类 Relay 操作使用可计数的传输边界；启动、前后台、配对、通话、短信、通知、手动反馈、重试及晚到回调都不能创建/发送 Relay 请求。不是只搜索源代码中某个布尔值。
3. 直连：Relay DNS/网络完全不可达时，LAN、热点和 Tailscale 已认证直连仍可配对与运行；身份错误、签名错误、重放和端口证明失败必须拒绝。
4. 数据：本地消息不丢失、不重复发送；退出不上传纯本地时段的旧云端事件；未完成命令不因切换而重新执行。
5. 多端：绑定切换、其他 iPhone 注册、本机 Android 退出及 AVF 未确认均不得伪造生效状态或解除策略。
6. 保持 PR #12/#13 的短信、通话归属、限时重试及既有 VoWLAN/VoBLE 测试通过。

### 真机

记录 iPhone 与 Android/AVF 两端对所有 AirSIM Relay 地址的实际请求，而不是以 Dashboard 离线代替。明确切换排空时间及测量窗口。分别测试前台、锁屏、系统回收、用户强退，不把其中一种结果推广到其他状态。

覆盖三星热点、普通 LAN、Tailscale；断网/重连/DHCP 换址；拨出、接听、拒绝、挂断、双向音频及短信。用户手动切换模式、重启两端、关闭蓝牙和 VPN 后不能出现云端回退。

建议实施顺序：统一策略与状态机 → Android/AVF 协商及出口关闭 → iOS 协调与全出口约束 → 顶部滑块/可访问性 → 自动化和抓包验收。具体提交粒度和测试命令在完整设计确认后制定实施计划。

## 8. 设计者补充的选择，待用户审阅

1. 活动通话时阻止模式切换，避免中途挂断。
2. Android 整机级禁用，但 iPhone 完成状态只对应当前绑定 Android；其他客户端不能自动解除。
3. 对端离线时退出保持待同步，不提前恢复本机云端。
4. GitHub 更新偏好不受“零 AirSIM Relay”影响。
5. AVF 必须参与确认；旧 Agent 明确显示需要升级，不宣称已关闭其云端。
6. 换绑不自动恢复旧 Android，快照按设备保留；退出只处理当前绑定设备。
7. Android 本机退出优先，iPhone 保持本机禁止 Relay并提示不一致，不自动重新开启对端。

这些是为了让实施可判断的设计选择，不冒充用户已逐条确认。业务代码未修改，部署与设备安装仍暂停。
