# 回到同一局域网后恢复 VoWLAN（Issue #2，候选 build 85）

目标：在“自动”模式中，离家时云端或蓝牙可用，回到安卓所在 Wi-Fi 后重新发现并认证 VoWLAN，不要求手动打开安卓界面。已配对且正常后台运行是前提。当前为本地候选，未安装、发布或上传 TestFlight；不能把代码修改视为用户机型已经验收。

## 模式与通话约束

- “自动”才按 VoWLAN → VoBLE → 云端选择；固定“云端”不会擅自改成本地。
- 连接 Wi-Fi 不代表 VoWLAN 已可用：仍须发现服务并通过现有带 HMAC 的健康检查，核对当前绑定设备及就绪状态。
- 本次通话建立后保持锁定链路。网络恢复任务遇到通话会等待；云端／蓝牙通话也不因本地发现成功而改用局域网轮询来电状态。
- 不更改用户模式，不新增 Relay 状态查询定时器，不重新配对或写入云端参数。

## 安卓恢复

VoWLAN 前台服务通过正常权限 `ACCESS_NETWORK_STATE` 观察 Wi-Fi NetworkCallback，不依赖默认网络是不是蜂窝／VPN，也不要求 Wi-Fi 已被系统验证为可上网。同一 IP 重新获取也使用网络 handle／接口／IPv4 的新快照触发恢复。网络事件合并后等待一秒稳定，并唤醒原本的本地服务检查循环；原五秒检查仍作为回退。

恢复先退休旧 NSD listener 身份，再重新注册 `_airsim-vowlan._tcp`；晚到的旧注册成功不能覆盖新状态。只是重建发现广播，不为此关闭已运行的控制／PCM Socket，不重启系统音频或媒体。地址确实消失时仍按既有策略处理路径失效，不做通话途中静默换链路。服务销毁后注销回调，迟到事件不得重启服务。事件写入可导出的本机日志，关键字 `vowlan_network_recovery`。

## iOS 恢复

只在允许 VoWLAN 的模式下启用 Wi-Fi 路径观察。初次监控快照不当成网络切换，避免使正在进行的配对／VPN 探测失效；实际变化使前一网络上的认证结果过期，取消旧恢复任务。

回到 Wi-Fi 后合并一秒，待无通话时重建 Bonjour 浏览，并在 0、2、5 秒间隔内进行有限次认证检查；成功即停止并刷新本地状态循环，失败保留其他可用链路及原恢复退避。自动模式已连 BLE 时也不再依赖原状态循环的提前返回来决定是否检查 VoWLAN。再次换网、切换到固定云端／蓝牙、清除配对或停止浏览都会使旧任务失效。

Verbose 事件为 `network_changed`、`network_recovered`、`network_recovery_pending`，不记录 SSID／配对密钥／短信／PCM。没有认证通过时不把 Wi-Fi 连接直接显示成 VoWLAN 在线。

## 系统边界与验收

iOS 被系统挂起时不能保证立刻执行路径回调；必须在获得后台运行机会、回前台或拨号前继续核对。安卓被 OEM 强制停止、后台服务受限或路由器隔离／屏蔽 mDNS 时，也不能仅靠 App 代码保证恢复。不要用高频 Relay 请求、虚假后台音频、永久唤醒锁或绕过系统限制作为替代。手动 IP 配对可绕过发现受限，但仍要求 IP 真正可达。

回归包含：同 IP 新网络恢复、重复通知合并、延迟事件失效、固定模式不回切、通话中不开始恢复、未配对不认证，以及云端／蓝牙通话不改为 VoWLAN 状态轮询。模拟测试与构建不能替代以下真机步骤：

1. 选择“自动”，保持安卓界面关闭；在同网确认 VoWLAN 已认证。
2. iPhone 关闭 Wi-Fi，确认使用另一可用链路；重新接入原 Wi-Fi，检查认证恢复，无需打开安卓。
3. 安卓断开再重接 Wi-Fi（包括得到相同 IP），重复上一步。
4. 保持云端通话时重新进 Wi-Fi，确认本通音频不切换；结束后下一通再选 VoWLAN。
5. 分别检查 BLE 已连接、锁屏后获得运行机会、固定云端模式，以及路由器不允许互访时不会误报在线。
