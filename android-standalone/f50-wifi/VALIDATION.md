# 验证记录

本组件只针对一台已经安装 Wi-Fi 客户端和 USB ADB 修复的 MU3356 B28。以下结果不外推到原厂固件或其他型号。

## 2026-11-17：独立供电失败后的底层修复

- 用户实际改接独立电源后，Mac 的 ADB 清单为空，路由器未观察到重新关联，HTTPS Relay 连续返回离线，本轮独立供电验收未通过。用户确认设备无电池，换电源必然断电重启；接回 Mac 后启动成功不能代替这次失败结果。
- 旧启动脚本在系统运行满 25 秒后要求 `sys.usb.state=ncm,mtp,adb`，不满足就退出；上层必须等待它创建地址保护就绪标记。改为检查系统启动完成，保留固件摘要、地址保护程序摘要、覆盖挂载与回退检查，USB 初始化脚本不变。断电前那轮日志未完整落盘，因此 USB 条件是已确认的代码缺陷，尚不能单凭日志宣称已证实全部失败原因。
- 本次候选只改动 ramdisk 的 `overlay.d/sbin/codex-f50-wlan-bridge.sh`，其他 41 项逐项相同，含 USB ADB、公钥和内嵌 DEX；AVB blob 相同。当前 runtime 不变，仍为 `ded94fcff81da6dfe9be68e4c63f19579ceb06629a5324d7ed2feb6ae0ddeb0e`。
- 写入前读取完整 8 MiB `init_boot_a`，摘要与此前可启动镜像一致；写入后完整回读与候选逐字节一致，SHA-256 为 `11d13ab7d4f6100c68e4912dc29feebd8468995b55e101bec03e2183f6c879b7`。工具报告分区恢复完成，写入前后 83 项分区表导出一致；未写其他镜像。
- Mac 连接状态下启动复验：USB ADB 在工具 reset 后约 24 秒恢复，写入/读回小文件逐字节一致；系统运行约 26 秒时地址保护就绪；随后自动连接指定 Wi-Fi，默认路由存在，公网 ping 4/4 成功。控制桥由监督器自动启动，状态 ready、启动次数 1，云端在线；没有手动启动 AirSIM。
- 本机 Java/D8 构建、PortalRulesTest、shell 语法与 Git 空白检查通过。
- **待最终复验：** 已请用户再次改接独立电源；只有观察到无 USB 主机的新开机自动联网，并由 iPhone 使用 4G/5G 通过云端自检，才能认定本轮目标完成。

## 2026-11-17：独立供电验收准备

- 已确认原 APK 的开机广播会启动 Standalone 前台服务，但既有固定端口的控制桥此前由 USB shell 手动启动。新增可选监督器复用该桥和原 token，不替换 APK、不改配对身份、只监听原 loopback 端口。
- 本机核验已安装 APK 签名后写入设备私有 pin，并显式启用监督。原 token 的私有持久副本权限为 0600；状态和日志不返回 token。
- 当前 runtime SHA-256：`ded94fcff81da6dfe9be68e4c63f19579ceb06629a5324d7ed2feb6ae0ddeb0e`。构建、PortalRulesTest 和 Git 空白检查通过。
- 已在两张 SIM 都为空闲状态时结束一次原桥接进程，监督器自动启动新进程，token 认证状态恢复为 ready，启动次数为 1；没有再次执行手动启动桥的命令。此项仍在 Mac 连接状态下测试。
- Wi-Fi 运行时不再把 USB 配置字符串作为额外条件，仍要求系统和既有地址保护就绪；原启动镜像的 USB 初始化与地址保护安装步骤保持不变。独立电源是否满足这些底层条件，不能由此代码修改直接推出。
- 已准备独立的 LAN 与 HTTPS Relay 状态观察器；初始化后不调用 ADB，不转发设备流量。观察器记录新开机 uptime、USB 主机状态、桥接健康和云端在线状态。
- **尚未验收：** 用户完成独立电源关机再开机、Mac 物理断开后自动联网/桥接启动，以及 iPhone 使用 4G/5G 的云端自检。等待实测前，不宣称“只接电源整套流程已通过”。

## 2026-11-17：热点配网、重启切换

- 本轮仅通过 USB 更新已安装服务的 runtime，没有刷写分区或更换 AirSIM APK。最终 runtime SHA-256：`79234f27518e5a43f78a4c9454e173737efb10a1be6ea3671e1646a202de1309`。旧 runtime、摘要与设置已在本机私有目录备份。
- 真机页面“仅保存”成功添加临时测试目标，原热点及 HTTP 页面继续可用；“保存并重启”触发整机重启，USB ADB 随后恢复为 `ncm,mtp,adb`。
- 不存在的测试目标：启动准备后仅尝试该目标，没有改连现场仍可用的另一个已保存网络；90 秒连接超时后自动恢复原热点。测试目标随后移除。
- 在恢复的热点上重启配置服务，发现 B28 对重复启动已运行热点返回失败；改为保留已运行的 hostapd 后复验，模式为 hotspot、无错误、ADB 可用。
- 新一次真实启动期间登录配置页，服务暂停自动切换；系统运行超过 185 秒后仍处于热点模式，超过原本 160 秒的切换门限，USB ADB 保持可用。随后可由页面主动重启退出配网。
- 按用户要求将门限从 160 秒改为 60 秒，并检查系统启动完成、USB ADB 及地址保护就绪。修正原厂在 STA 重启后不主动开热点的行为：最终版本实测系统运行约 28 秒时热点开启，65 秒时热点关闭，72 秒时指定网络取得地址和默认路由；从页面提交重启到联网约 100 秒（包含关机、系统引导）。这不是“点击重启后 60 秒必定联网”的承诺。
- 最终重启后管理密码与指定网络保持，USB 读写往返、`ncm,mtp,adb`、runtime 摘要与加载路径均通过；`ifconfig wlan0 0.0.0.0` 地址保护仍通过。AirSIM 云端记录在线；其桥接进程按既有方式通过 USB 恢复，本轮没有验收脱离 Mac 的冷启动通话。
- 最终一分钟版本绑定 wlan0 连续公网 ping：60/60 成功、0% 丢包，覆盖约 59 秒，平均 7.47 ms。此项是有限时段验证，不代表全天运行。
- 新接口验证通过：未登录重启拒绝、Origin/CSRF 拒绝、空 SSID 拒绝、旧立即连接接口拒绝、状态不返回密码、热点扫描明确返回不可扫描。
- Java/D8 构建、PortalRulesTest、JavaScript 语法与 git diff 空白检查通过。新版真实页面在 390px 与 1280px 检查，手机无横向溢出；独立 UI 复核两项重启反馈修正均 resolved，限定 disposition 为 ship，不代替硬件测试。

- 保存并连接第二个 WPA2 测试网络，取得不同 IPv4；公网 4/4 ping 成功。修正后的一次启动在系统运行约 170 秒自动连接该测试网络并取得地址和默认路由。
- 随后执行普通 `adb reboot`：USB ADB 约 49 秒恢复，配置服务自动加载数据目录校验通过的 runtime。它先尝试上次选择的测试网络，该轮未及时取得 DHCP 地址，随后自动改连另一已保存网络，在约 4 分钟内恢复地址和路由。不能将这轮写成测试网络 DHCP 始终稳定。

- 临时路由器测试 AP 已关闭，原无线配置逐字节恢复；仅移除了本轮新增的测试网络配置。
- 当前网络已通过 `/system/bin/ifconfig wlan0 0.0.0.0` 命令保护回归：返回成功、地址保持不变。局域网配置页 HTTP 200，管理密码与自动连接选择在重启后保留。AirSIM 云端心跳重新在线，未测试真实电话。
- 最后绑定 wlan0 连续探测公网 120 次，120/120 成功、0% 丢包，覆盖约 119 秒。该有限时间窗口不代表全天稳定性。

### 发现并修正的问题

- B28 的 shell Context 仍保留 `android` AppOps 身份：显式使用 shell 的 op package 和 AttributionSource。
- 无头进程通过 Settings ContentResolver 写 `wifi_on` 被拒绝：改用设备已支持的 `settings put global wifi_on 0`，不在命令参数里传 Wi-Fi 密码。
- Android 重启会重排 networkId：持久选择改为 SSID 和加密方式，在开机连接时重新解析编号。
- PSK/SAE 过渡网络重复返回同一编号：列表按 networkId 去重。
- Android API 只移除 SSID/密码的外层引号：保留内部引号和反斜线，不套用 shell 转义。对应 [AOSP NativeUtil](https://android.googlesource.com/platform/packages/modules/Wifi/+/refs/heads/android15-release/service/java/com/android/server/wifi/util/NativeUtil.java) 的字符串契约。
